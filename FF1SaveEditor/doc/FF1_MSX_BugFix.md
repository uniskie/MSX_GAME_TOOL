## 2. メモリ配置と常駐アーキテクチャ

### 1. メモリ領域の種別と制約

`BATTLE.COM` 実行時のメモリ空間（`0x8000`〜`0xBFFF`）および関連メインRAMの配置と役割は以下の通りです。

- **`0x3400` 〜 `0x351F` 【戦闘時 味方実効バッファ】（288バイト）**:
  パーティ4人分の戦闘パラメータ（各72バイト）。
- **`0x3520` 〜 `0x362D` 【戦闘時 敵実効バッファ】（270バイト）**:
  出現敵最大9体分の戦闘パラメータ（各30バイト）。
- **`0x362E` 〜 `0x36FF` 【戦闘バッファ直後領域】（210バイト） -> 常駐領域B**:
  初期化時のゼロクリア（`0x8C66`）以降、戦闘終了まで読み書きされない領域。初期化クリア長を縮小して保護し、パッチコード群を常駐させます。
  - 通常時: 計157バイト常駐（残り空き 53バイト）
  - オートターゲット有効時: 計209バイト常駐（残り空き 1バイト）
- **`0x3700` 〜 `0x3FFF` 【メッセージ・魔法名バッファ】**:
  街・戦闘のメッセージベクタおよび魔法名表示展開領域（侵食不可）。
- **`0x8000` 〜 `0xBC5F` 【コード＆固定データ領域】**:
  戦闘プログラム本体および固定テーブル群。
- **`0xBC60` 〜 `0xBCDC` 【戦闘用ワークエリア】（125バイト）**:
  コマンド入力、敵配置座標、行動順テーブル等。戦闘中常時更新。
- **`0xBCDD` 〜 `0xBCFF` 【未使用パディング領域】（35バイト） -> 常駐領域A**:
  `BATTLE.COM` バイナリ内の空き領域。直接書き込み可能。計32バイト常駐（残り空き 3バイト）。
- **`0xBD00` 〜 `0xBFFF` 【PSG演奏・描画ワークエリア】**:
  `MAIN.COM` 常駐のサウンド演奏ドライバ用ワーク領域。エンカウント時のディスクアクセス前にBGMは停止されるため、ロード直後はディスクから読まれたバイナリ内容が保持されます。戦闘BGM開始（`0x8047`）以降にワークとして上書きされます。

### 2. 配置設計の方針

1. **インライン余剰枠の活用（固定配置）**:
   パッチ07-W（敵睡眠解除判定）で生じた余剰枠（`0xBA11`〜`0xBA1A`、10バイト枠）に、8バイトにスリム化したパッチ06（アイテム沈黙チェック回避）を固定配置します。これにより常駐領域Aからパッチ06が外れ、常駐領域Aを他のパッチへ開放します。
2. **常駐領域A（`0xBCDD`〜`0xBCFF`, 35バイト枠）**:
   ディスク上のバイナリ（オフセット `0x3CDD`〜）に直接パッチコードを格納します（実行時転送不要）。
   - パッチ07: 敵耐性・命中率保存 (16バイト: `0xBCDD`〜`0xBCEC`)
   - パッチ11保存: 味方攻撃力・命中率保存 (16バイト: `0xBCED`〜`0xBCFC`)
   - 未使用余白: 3バイト (`0xBCFD`〜`0xBCFF`)
3. **常駐領域B（`0x362E`〜`0x36FF`, 210バイト枠）**:
   ディスク末尾（`0xBD10`〜）に実体ブロックを格納し、起動時（`0x8004`）に `0x362E` へ `LDIR` 転送して常駐させます。
   - プレイヤー毒2ダメージ: `P_POISON` (11バイト: `0x362E`〜`0x3638`)
   - パッチ11読込: `P11_LOAD` (16バイト: `0x3639`〜`0x3648`)
   - パッチ13: `P13_LVUP` (12バイト: `0x3649`〜`0x3654`)
   - パッチ14: `P14_INTEL` (40バイト: `0x3655`〜`0x367C`)
   - パッチ16: `P16_MONK` (24バイト: `0x367D`〜`0x3694`)
   - パッチ15: `P15_REGEN` (54バイト: `0x3695`〜`0x36CA`)
   - オートターゲット本体（オプション指定時）: `AUTO_TARGET` (52バイト: `0x36CB`〜`0x36FE`)
   - 未使用余白: 通常時 53バイト / オートターゲット時 1バイト (`0x36FF`)
4. **初期化ゼロクリア範囲の縮小**:
   `0x8C66`（ファイルオフセット `0x0C67`）のクリア長を `0x02FF` から `0x022D` へ縮小し、バッファ（`0x3400`〜`0x362D`）のみをクリアして `0x362E`〜`0x36FF` のパッチコードを保護します。
5. **スタックポインタ（SP）保存の保護**:
   `0x8000` の `LD (.X80C2), SP` は書き換えません。SPが正規に退避された直後の `0x8004` からローダーを実行し、転送完了後に `JP 7394H` でフェードアウト処理へ合流します。

## 4. 各パッチの技術詳細とアセンブリコード

### 起動時転送ルーチン (0x8004 フック & 0xBD00 ローダー)

- **概要**: `0x8000` でスタックポインタが `.X80C2` へ退避された直後の `0x8004` をフックします。`0xBD10` に格納されている210バイトの実体ブロックを `0x362E` へ `LDIR` 転送し、本来呼ばれるはずだった `0x7394`（フェードアウト）へ `JP` で合流します。

```asm
; --- 呼び出し元フック (0x8004 〜 0x8006: 3バイト) ---
8000: ED 73 C2 80    LD   (.X80C2), SP ; スタックポインタ退避 (元コードのまま無変更)
8004: CD 00 BD       CALL 0BD00H       ; 本来の CALL 7394H を差し替え

; --- ローダー本体 (0xBD00 〜 0xBD0F: 16バイト) ---
BD00: 21 10 BD       LD   HL, 0BD10H   ; 転送元: ファイル末尾パッチ実体ブロック
BD03: 11 2E 36       LD   DE, 362EH    ; 転送先: 常駐領域B (0x362E)
BD06: 01 D2 00       LD   BC, 00D2H    ; 転送サイズ: 210バイト
BD09: ED B0          LDIR              ; 0x362E へ一括コピー
BD0B: C3 94 73       JP   7394H        ; フェードアウト処理へ合流 (復帰先は 0x8007)
BD0E: 00 00          NOP  NOP
```

### パッチ01: 逃走バグ (Running Bug) の修正

- **原因**: `0xB3B3` にて逃走実行キャラの戦闘バッファを `IY` に計算しているにもかかわらず、直後のレベル取得（`0xB3B9`）および運取得（`0xB3C2`）で `IX`（直前のキャラのポインタ）を参照しています。
- **修正**: 参照プレフィックスを `DD`（IX）から `FD`（IY）へ変更します。

```text
0xB3B9: FD 7E 26    LD A, (IY+26H)  ; レベル取得
0xB3C2: FD 7E 14    LD A, (IY+14H)  ; 運取得
```

---

### パッチ02: 敵の味方全体魔法バグ (Enemy Magic All Allies Bug) の修正

- **原因**: `0x9B5C` の `JR Z, .X9B88` により、詠唱者自身のスロット番号と一致する対象への効果適用を除外しています。
- **修正**: 条件分岐を `NOP` 2個で無効化し、詠唱者自身にも全体魔法（ケアルラ等）がかかるようにします。

```text
0x9B5C: 00 00       NOP NOP
```

---

### パッチ03: 戦闘終了後並び替えバグ (Sort Bug) の修正

- **原因**: 状態異常コードの比較において、`0x00`（正常）のみを生存優先度 `5` と判定しているため、毒（`0x04`）のキャラクターが死亡（`0x01`）や石化（`0x02`）と同列に扱われ、隊列の末尾に送られていました。
- **修正**: `CP 00H` を `AND 03H`（bit 0: 死亡、bit 1: 石化のマスク）に変更します。毒（`0x04`）はマスク結果が 0 となり、正常キャラと同様に優先度 5 として扱われます。

```text
0x8A4E: E6 03       AND 03H
0x8A58: E6 03       AND 03H
```

---

### パッチ04: 戦闘行動順の偏り (Battle Order Bug) の改善

- **原因**: 行動順初期テーブルが「敵（0〜8）→ 味方（0x80〜0x83）」となっており、シャッフル回数が 17回（`0x11`）しかないため、初期位置が前の敵に偏って先制行動が発生していました。
- **修正**: シャッフル回数を 17回 から 64回（`0x40`）へ増加させます。

```text
0x8322: 40          LD B, 40H
```

### パッチ05: 武器特効の到達不能 ＆ 属性参照ミスの修正 (Weapon Data Bug)

- **原因**:
  1. 味方攻撃時ルーチン `0x9342` において、属性・特効のロード元を誤って未使用領域 `+43H`, `+44H`（常に0）から読み出しています（正規バッファは `+46H`, `+47H`）。
  2. 味方攻撃時の敵パラメータロードルーチン `0x938E` において、特効判定ルーチン `0x9545` が `.X9855` を弱点比較用、`.X9856` を種族比較用として参照しているにもかかわらず、`+10H`（耐性）を `.X9855` に、`+12H`（弱点）を `.X9856` に格納しています。
  3. 暗闇判定直後の `0x9544: RET` により、後続の特効判定処理（`0x9545`〜）が到達不能になっています。
  4. 敵対象パラメータ読込ルーチン `0x9C13`（`0x9C4C`〜`0x9C57`）において、弱点属性（`+12H`）を `.XA216` へ読み込んだ直後、誤って種族属性（`+13H`）で同じアドレスを上書きしています。
- **修正**:
  - 味方武器のロード元オフセットを `+46H`（属性）および `+47H`（特効）に修正します。
  - 敵パラメータロードルーチンにおいて、弱点属性（`+12H`）を `.X9855` に、種族属性（`+13H`）を `.X9856` に格納するよう修正します。
  - `0x9537` のジャンプ先を `0x9545` へ調整し、`0x9544` の `RET` を `NOP` 化して特効判定へ通過させます。
  - `0x9C52`〜`0x9C57`（6バイト）を `NOP` 化し、弱点属性の上書き破壊を解除します。

```text
0x9359: 46          LD A, (IX+46H)  ; 武器属性ロード
0x935F: 47          LD A, (IX+47H)  ; 武器特効ロード
0x93A5: 12          LD A, (IY+12H)  ; 敵弱点属性 -> .X9855
0x93AB: 13          LD A, (IY+13H)  ; 敵種族属性 -> .X9856
0x9537: 0D          JR Z, $+15      ; 特効処理（0x9545）へジャンプ
0x9544: 00          NOP             ; 暗闇時も特効処理へ通過
0x9C52: 00 00 00 00 00 00            ; 種族属性による弱点上書きを解除 (NOP)
```

### パッチ06: サイレス時アイテム使用不可バグ (Mute Bug) の修正

- **原因**: アイテム使用時も魔法共通ルーチン `0x9871` を経由するため、沈黙判定 `0x9ABC` が無条件に実行されていました。
- **修正**: インライン余剰枠 `0xBA11` に8バイトサブルーチンを配置し、コマンド種別（`.XBCC8`）がアイテム（1以上）の場合は即座に `Carry=0` で復帰、魔法の場合は `0x9ABC` へジャンプします。

```asm
; --- 呼び出し元 (0x987D: 3バイト) ---
987D: CD 11 BA      CALL 0BA11H

; --- パッチ本体 (固定枠: 0xBA11 〜 0xBA18: 8バイト) ---
BA11: 3A C8 BC      LD   A, (.XBCC8)  ; コマンド種別取得
BA14: B7            OR   A
BA15: C0            RET  NZ           ; アイテムなら Carry=0 で即復帰
BA16: C3 BC 9A      JP   9ABCH        ; 魔法なら正規沈黙チェックへ末尾ジャンプ
```

### パッチ07: デスペル耐性 ＆ 敵命中率書き戻し (Dispel Bug / 11-D, 11-H)

- **原因**: 敵対象パラメータ反映処理 `.X9C71` において、耐性属性（`+10H`）および命中率（`+0BH`）を敵バッファへ書き戻すコードが欠落していました。
- **修正**: フック元で攻撃力（`+0CH`）を書き戻し、常駐領域A（`0xBCDD`）にて耐性属性と命中率を敵バッファへ保存します。

```asm
; --- 呼び出し元 (0x9CA7 〜 0x9CAD: 7バイト) ---
9CA7: CD DD BC      CALL 0BCDDH       ; 耐性・命中保存サブルーチン呼出
9CAA: DD 77 0C      LD   (IX+0CH), A  ; 攻撃力保存
9CAD: C9            RET

; --- パッチ本体 (常駐領域A: 0xBCDD 〜 0xBCEC: 16バイト) ---
BCDD: 3A 17 A2      LD   A, (.XA217)  ; 耐性属性
BCE0: DD 77 10      LD   (IX+10H), A  ; 耐性保存 (11-D)
BCE3: 3A 09 A2      LD   A, (.XA209)  ; 命中率
BCE6: DD 77 0B      LD   (IX+0BH), A  ; 命中率保存 (11-H)
BCE9: 3A 1B A2      LD   A, (.XA21B)  ; 攻撃力をロードして復帰
BCEC: C9            RET
```

### パッチ07-W: 敵睡眠解除判定の固定確率化 (Enemy Waking Bug)

- **原因**: `0xBA08` において、敵の最大HPと乱数（0〜80）を減算比較し、最大HPが乱数を上回る場合に目を覚ます処理を行っています。このため最大HPが80以上の敵は毎ターン100%確実に目覚め、睡眠状態が持続しませんでした。
- **修正**: 乱数取得ルーチン（`0x5085`）により約10%（25/256、値が `0x19` 未満）の固定確率で目覚めるよう差し替えます。目覚める場合は直ちに `0xBA1B`（RES 5）へ直行させ、末尾の `0xBA11`〜`0xBA1A`（10バイト）をパッチ06用の空き枠として開放します。

```asm
; --- 呼び出し箇所: BATTLE.COM 0xBA08 〜 0xBA1A (19バイト枠) ---
BA08: CD 85 50      CALL 5085H        ; 乱数 0..255 取得 (3バイト)
BA0B: FE 19         CP   19H          ; 25/256 (約9.8%) の解除判定 (2バイト)
BA0D: 30 14         JR   NC, 0BA23H   ; 目覚めない場合はメッセージ表示へ (2バイト)
BA0F: 18 0A         JR   0BA1BH       ; 目覚める場合は RES 5 へ直行 (2バイト)
; 0xBA11 〜 0xBA1A: パッチ06 (8バイト) 配置先枠
```

### パッチ08: ヒーラ効果値正常化 (Healara Effectivity Bug)

- **修正**: 本来のレベル5相当効果値である `0x18`（24）に書き換えます。

### パッチ09: シェイラ効果ルーチン番号修正 (LOK2 Bug / 11-A)

- **修正**: 本来の回避低下ルーチン番号 `0x0E` に変更します。

### パッチ10: 回避率バグ解消＆攻撃力1.25倍正常化 (Evasion Bug)

- **原因**: `0x9571` において、防御側が睡眠・麻痺の際に攻撃力1.25倍を計算した後、直ちに `RET` して通常命中計算ルーチン（`0x958C`）をスキップしていました。このため命中率が基礎値168固定となり、高レベルでも空振りが多発していました。
- **修正**: フック元（`0x9571`〜`0x958B`, 27バイト枠）に直接インライン実装します。防御側回避率（`.X9857`）を 0 クリアし、16bit精度のまま攻撃力1.25倍を計算して通常命中計算（`0x958C`）へ合流させます。

```asm
; --- インライン実装 (0x9571 〜 0x958B: 27バイト) ---
9571: 3A 54 98      LD   A, (.X9854)  ; 防御側状態異常
9574: E6 30         AND  30H          ; 睡眠(20H) または 麻痺(10H)？
9576: 28 14         JR   Z, 958CH     ; 正常なら 958CH へジャンプ
9578: AF            XOR  A
9579: 32 57 98      LD   (.X9857), A  ; 防御側回避率 = 0
957C: 2A 6B 98      LD   HL, (.X986B) ; HL = 基礎攻撃力 (16bit)
957F: EB            EX   DE, HL       ; DE = 基礎攻撃力
9580: CB 3A         SRL  D            ; DE = 攻撃力 / 4
9582: CB 1B         RR   E
9584: CB 3A         SRL  D
9586: CB 1B         RR   E
9588: 19            ADD  HL, DE       ; HL = 攻撃力 + 攻撃力/4 = 1.25倍
9589: 22 6B 98      LD   (.X986B), HL ; 実効攻撃力保存 (16bit)
; 958CH の通常命中率計算ルーチンへそのまま合流
```

### パッチ11: ストライ＆セーバー味方対象パラメータ反映 ＆ 効果番号修正 (11-B, 11-C)

- **原因**:
  1. `BDATA.TBL`（`0x0254`）において、ストライ（TMPR）の効果ルーチン番号がセーバーと同じ `0x0D`（命中+攻撃力UP）に設定されていました。
  2. 味方を対象に魔法をかける際、味方バッファから攻撃力（`+20H`）と命中率（`+21H`）をワークに読み込まず、終了後も書き戻していませんでした。
- **修正**:
  - `BDATA.TBL`（`0x0254`）の効果番号を `0x0B`（攻撃力のみUP）へ変更します。

9C0D: 3E 00         LD   A, 00H

### パッチ13: 複数レベルアップ対応 (Multiple Level Up Bug)

- **原因**: 経験値加算ルーチン `0x8538` において、1回レベルアップ処理（`0x867B`）を呼ぶとそのまま次キャラの判定へ抜けてしまい、累積経験値による連続レベルアップ判定が行われていませんでした。

### パッチ14: 知性の魔法威力反映・ディア系＆回復2倍対応 (11-F)

9AB8: 00 00 00 00   NOP  NOP NOP NOP

; --- パッチ本体 (常駐領域B: 0x3655 〜 0x367C: 40バイト) ---
3655: FD 7E 07      LD   A, (IY+07H)

366C: 21 00 A2      LD   HL, 0A200H   ; 基礎威力バッファ
366F: FE 07         CP   07H          ; 回復魔法？

.HEAL:

### パッチ15: プレイヤー毒2ダメージ ＆ 敵リジェネレーション処理 (Enemy Poison/Regen Bug)

#### ① プレイヤー毒2ダメージ処理

- **原因**: ターン終了時の毒減算において、`0x84EB: DEC HL` で1ダメージしか引かれていませんでした。
- **修正**: フック元から常駐領域B（`0x362E`）を呼び出し、HP-2減算しつつ元HPが1または2の場合でも安全にHP=1を維持します。

```asm
; --- 呼び出し元 (0x84EA 〜 0x84EE: 5バイト) ---
84EA: CD 2E 36      CALL 0362EH       ; 毒2ダメージサブルーチン呼出
84ED: 38 0F         JR   C, 084FEH    ; Carry=1 (元HP=1) なら書き戻しスキップ

; --- パッチ本体 (常駐領域B: 0x362E 〜 0x3638: 11バイト) ---
362E: 2B            DEC  HL           ; HP - 1
362F: 7C            LD   A, H
3630: B5            OR   L
3631: 37            SCF
3632: C8            RET  Z            ; 元HP=1なら Carry=1 で復帰 (書き戻しスキップ)
3633: 2B            DEC  HL           ; HP - 2 (元HP>=2)
3634: 7C            LD   A, H
3635: B5            OR   L
3636: C8            RET  NZ           ; 元HP>=3ならそのまま復帰 (Carry=0)
3637: 23            INC  HL           ; 元HP=2なら HL=1 に補正
3638: C9            RET               ; Carry=0 で復帰
```

#### ② 敵リジェネレーション処理

- **原因**: 敵の種族属性 bit 7（`0x80` = 再生）を持つモンスター（トロール、キメラ等）のHP回復処理が実装されていませんでした。
- **修正**: 味方ループ終了時（`0x8504`）をフックし、常駐領域B（`0x3695`）で敵スロット（0〜8）を走査。種族属性 bit 7（再生）を持つ生存敵のHPを +2 回復（最大HPを超えないようクリッピング）します。

```asm
; --- 呼び出し元 (0x8504 〜 0x8508: 5バイト) ---
8504: C3 95 36      JP   03695H
8507: 00 00         NOP  NOP

; --- パッチ本体 (常駐領域B: 0x3695 〜 0x36CA: 54バイト) ---
3695: DD 21 20 35   LD   IX, 3520H    ; 敵バッファ先頭
3699: 06 09         LD   B, 09H       ; 9体ループ
.LOOP:
369B: DD 7E 13      LD   A, (IX+13H)  ; 種族属性
369E: 07            RLCA              ; bit 7 (再生) を Carry へ
369F: 30 1E         JR   NC, .NEXT    ; 再生なしなら即スキップ
36A1: DD 6E 04      LD   L, (IX+04H)  ; 現在HP読込
36A4: DD 66 05      LD   H, (IX+05H)
36A7: 7C            LD   A, H
36A8: B5            OR   L
36A9: 28 14         JR   Z, .NEXT     ; 未出現/死亡はスキップ
36AB: 23            INC  HL           ; HP + 2
36AC: 23            INC  HL
36AD: DD 5E 1B      LD   E, (IX+1BH)  ; 最大HP読込
36B0: DD 56 1C      LD   D, (IX+1CH)
36B3: CD F0 80      CALL 80F0H        ; HL > DE 判定
36B6: 38 01         JR   C, .SAVE     ; HL <= DE ならクリッピング不要
36B8: EB            EX   DE, HL       ; 最大HPでクリッピング
.SAVE:
36B9: DD 75 04      LD   (IX+04H), L  ; HP書き戻し
36BC: DD 74 05      LD   (IX+05H), H
.NEXT:
36BF: 11 1E 00      LD   DE, 001EH    ; 次の敵スロット (+30バイト)
36C2: DD 19         ADD  IX, DE
36C4: 10 D5         DJNZ .LOOP
36C6: FD E1         POP  IY           ; レジスタ復帰 (元処理)
36C8: DD E1         POP  IX
36CA: C9            RET
```

### パッチ16: モンク素手防御力計算の実装 (Monk Armorless Defense)

### オートターゲット処理 (オプション機能: `--auto-target`)

- **概要**: 選択した敵が手番前に死亡している場合、自動的にスロット0から生存敵を探索して対象を切り替えます。
- **共存設計**: 常駐領域Bの末尾（`0x36CB`〜`0x36FE`, 52バイト）に本体を配置し、敵リジェネレーション処理やプレイヤー毒2ダメージと両立します。

```asm
; =============================================================================
; オートターゲット本体サブルーチン (常駐領域B 0x36CB 〜 0x36FE: 52バイト)
; 入力: .XBCD6 (対象スロット番号)
; 出力: .XBCD6 (必要時更新), Carry=0 (正常復帰) / Carry=1 (敵全滅)
; =============================================================================
AUTO_TARGET:
36CB: C5             PUSH BC             ; レジスタ退避
36CC: D5             PUSH DE
36CD: E5             PUSH HL
36CE: 3A D6 BC       LD   A, (.XBCD6)    ; 対象スロット取得
36D1: FE 09          CP   09H            ; 敵単体スロット (0〜8) か？
36D3: 30 25          JR   NC, .EXIT_OK   ; 味方や全体なら何もしない (Carry=0)

    ; 現在の対象敵が生存しているか確認
36D5: 5F             LD   E, A
36D6: 16 00          LD   D, 00H
36D8: 21 66 BC       LD   HL, 0BC66H     ; 敵IDテーブル先頭
36DB: 19             ADD  HL, DE
36DC: 7E             LD   A, (HL)
36DD: FE FF          CP   0FFH           ; 0xFF (死亡) か？
36DF: 20 19          JR   NZ, .EXIT_OK   ; 生存中ならそのまま復帰 (Carry=0)

    ; 死亡しているためスロット0から生存敵を探索
36E1: 21 66 BC       LD   HL, 0BC66H
36E4: 06 09          LD   B, 09H         ; 最大9体ループ
36E6: 0E 00          LD   C, 00H         ; C = スロット番号 (0〜8)
.LOOP:
36E8: 7E             LD   A, (HL)
36E9: FE FF          CP   0FFH
36EB: 20 09          JR   NZ, .FOUND     ; 生存敵発見
36ED: 23             INC  HL
36EE: 0C             INC  C
36EF: 10 F7          DJNZ .LOOP
    ; 全員死亡時
36F1: E1             POP  HL             ; レジスタ復帰
36F2: D1             POP  DE
36F3: C1             POP  BC
36F4: 37             SCF                 ; Carry=1 (全滅)
36F5: C9             RET

.FOUND:
36F6: 79             LD   A, C           ; A = 新スロット番号
36F7: 32 D6 BC       LD   (.XBCD6), A    ; 対象スロット更新
.EXIT_OK:
36FA: E1             POP  HL             ; レジスタ復帰
36FB: D1             POP  DE
36FC: C1             POP  BC
36FD: B7             OR   A              ; Carry=0 (正常)
36FE: C9             RET
```

### パッチ01-M: ガイアの妖精の泉タイル復元 (SUB05.MAP 展開・再圧縮)

- **原因**:
  - ガイアの町のマップデータ（`SUB05.MAP`）において、泉の南側水際マスに会話メッセージ判定（メッセージ `0xF7`:「すきとおった みずが わきでている」）を持つタイル `0x3B` (59) ではなく通常タイルが配置されていたため、調べても何も反応しませんでした。
- **データ構造と展開仕様**:
  - サブマップ（64×64 = 4,096タイル）は可変長ランレングス形式で圧縮されています。
    - 最上位bit = 0 (`0x00`〜`0x7F`): 単一タイルID
    - 最上位bit = 1 (`0x80`〜`0xFE`): タイルID ＝ `(バイト値 & 0x7F)`、次バイト ＝ 連続数（0なら256）
    - `0xFF`: 終端マーカー
- **修正手順**:
  1. `SUB05.MAP` の圧縮ストリームを 4,096 バイトの平文タイル配列へ展開します。
  2. プレイヤーが南側から調べる水際座標（Y=19, X=45〜50 の計6マス）のタイルIDを `0x3B` (59) に置換します。
  3. 平文配列を可変長ランレングス形式で再圧縮し、末尾に `0xFF` を付加します。
  4. 再圧縮後のサイズがディスク上の格納領域（セクタ722〜724、3セクタ = 1,536バイト）に収まることを検証し、余剰領域を `0x00` でパディングして書き戻します。

## 5. 調査・検証完了および保留項目の整理

1. **カヌー表示バグ (No Canoe in Item List Bug)**:
   - MSX版では、カヌー入手イベント（`SMAP.COM`）、河川進入判定（`MAIN.COM`）、重要品一覧展開（`MENU.COM`）のすべてが同一のメモリ番地 **`0xC210`** を参照・更新するように設計されています。FC版のようなフラグ不整合は発生しないため、対応不要です。
2. **宿泊アイテム（コテージ・テント）のセーブ順序およびMP回復**:
   - キャラクタMP領域の構造は `0xC120`〜 が「現在MP」、`0xC128`〜 が「最大MP」となっており、コテージ使用処理（`MENU.COM: 0x9CA4`）では最大MPから現在MPへの全回復コピーが正しく行われています。
   - また、このMP回復処理の後にセーブ処理が実行されているため、FC版の「House Bug」はMSX版には存在せず、正常に動作しています。
3. **キャラバン着陸 (Caravan Landing Bug)**:
   - MSX版では飛空艇が砂漠のオアシス（キャラバン）に着陸できても、飛空艇消失やスタック等の進行停止は発生しません。ゲーム進行上の実害がなく、プレイヤーの利便性としても定着しているため、パッチ対象から除外しました。
4. **複数状態異常魔法のメッセージ誤表示 (11-G)**:
   - 付与判定自体は正常に行われており、表示テキストのみ「こうかが なかった」が優先される現象です。実害が軽微なため、コード容量と複雑化の観点から保留としています。
5. **NPC初期配置ミス (Lost Sprites Bug / #10)**:
   - **コーネリア城1Fの女性NPC**: MSX版の初期配置データ（`EXDATA1.COM 0x0070`〜）ではタイル座標 X=30 (`0x1E`), Y=11 (`0x0B`) に配置されており、属性フラグ領域（`+0x08`, `+0x09`）も `0x00`（室外）で初期化されています。MSX2版はビットマップ画面（SCREEN 5）で一枚絵として描画しており、常時正常に表示されるためバグは存在しません。
   - **滝の洞窟のコウモリ**: MSX版の滝の裏の洞窟（マップ `0x24` / `EXDATA2.COM 0x0400`〜）にはロボット1体のみが配置されており、コウモリNPC自体が存在しません。
   - 以前の検討で指定されていたオフセットはエルフの街（マップ `0x08`）やアースの洞窟B3（マップ `0x12`）の別マップNPCを指していたため、パッチ対象から除外（対応不要）と整理しました。
6. **会話・進行フラグ・4大祭壇調査 (Dialogue Bug / `SMAP.COM`)**:
   - **オンラク潜水艇前の老人**: MSX版ではオンラクの老人（`0x97EE` / NPC ID `0x99`）がすでに正しい水のオーブ（`0xC212`）を参照しており、バグは存在しません。（`0x9448` / NPC ID `0x5D` はドワーフの洞窟の住民であり、正常な土のオーブ `0xC214` を参照しています）
   - **クレセント湖の12賢者**: FC版で不具合があった Text `94`/`9D` 担当の賢者に相当する MSX版のNPC（`0x96EF` / NPC ID `0x7E`）には、すでに4オーブ全点灯の判定が実装済みです。（`0x971B` / NPC ID `0x7F` は土のオーブ点灯後〜火のオーブ点灯前のみ専用ヒント `0x95` を話す別の賢者です）
   - **4大祭壇の調査メッセージ判定**: MSX版の調査判定（`0x8077`）は、`CP 0AH` と `CP 02H` のみを除外するコードへ書き直されており、4つの祭壇すべてを通過します。また、`SUBx.CHR` は FC版と同一データであり祭壇タイルにテレポート用の `0x40` ビットは付かないため、`SMAP.COM` に対する修正は不要です。
   - Dialogue Bug に分類される項目のうち、MSX版で修正が必要なものは **パッチ01-M（`SUB05.MAP` のガイアの妖精の泉タイル復元）のみ** です。
