# 1. `data[0]`（第1バイト：移動・地形・特殊イベント属性）

主に**「どの乗り物・移動手段で入れるか」「特殊な地形か」「重要イベントが発生するか」**を制御します。

### ビット対応表

|  ビット   | マスク値 | 属性名               | `0` のとき           | `1` のとき                             |
| :-------: | :------: | :------------------- | :------------------- | :------------------------------------- |
| **Bit 0** |  `0x01`  | 徒歩進入制限         | 徒歩で**進入可能**   | 徒歩で**進入不可**                     |
| **Bit 1** |  `0x02`  | カヌー進入制限       | カヌーで**進入可能** | カヌーで**進入不可**                   |
| **Bit 2** |  `0x04`  | 船進入制限           | 船で**進入可能**     | 船で**進入不可**                       |
| **Bit 3** |  `0x08`  | 飛空艇着陸制限       | 飛空艇が**着陸可能** | 飛空艇が**着陸不可**                   |
| **Bit 4** |  `0x10`  | 森林属性             | 通常地形             | **森林**（キャラの下半身が隠れる描画） |
| **Bit 5** |  `0x20`  | 船の接岸港           | 接岸不可             | **船の乗り降り可能**（港・海岸）       |
| **Bit 6** |  `0x40`  | 特殊イベント（下位） | （下記参照）         | （下記参照）                           |
| **Bit 7** |  `0x80`  | 特殊イベント（上位） | （下記参照）         | （下記参照）                           |

### 各ビットの詳細解説

* **Bit 0〜3（進入・着陸禁止フラグ）**
  * この4ビットはすべて**「1のときに進入（着陸）を禁止する」**ネガティブフラグです。
  * `m_move_walk.SetCheck(!(data[0] & 0x01));` のように、ビットが `0`（クリア）のときにその移動手段が許可されます。
  * 飛空艇（Bit 3）は空を飛んで移動するため移動中の進入判定としては使われず、**「着陸できるかどうか」**の判定として使われます。
* **Bit 4（森林属性 `0x10`）**
  * このビットが立っているタイルに入ると、キャラクターの下半分が木々のグラフィックの背後に隠れる描画処理が行われます。
* **Bit 5（船の接岸属性 `0x20`）**
  * 船に乗っている状態で陸地へ降りる、または陸地から船に乗り移るための境界マス（港や特定の海岸）に設定されます。
* **Bit 6・7（特殊イベント判定 `data[0] & 0xC0`）**
  * この2ビットの組み合わせ（4通り）で、マスを踏んだときの特殊イベントを判定します。
  * `0x00`（`00`）：特殊イベントなし（通常のタイル）
  * `0x40`（`01`）：**チャイム**（「チャイム」を持っているとミラージュの塔へ進入可能）
  * `0x80`（`10`）：**キャラバン**（オアシスでキャラバンの店・会話へ移行）
  * `0xC0`（`11`）：**飛空艇浮上**（「ふゆうせき」を持ってリュカーン砂漠の該当マスを踏むと飛空艇が浮上）

# 2. `data[1]`（第2バイト：テレポート／戦闘エンカウント属性）

`data[1]` は、**最上位ビット（Bit 7）が `1` か `0` かによって、残りのビット（Bit 0〜6）の意味が完全に切り替わる**構造になっています。

```
[Bit 7 = 1 の場合]  [ 1 ][  テレポート先ID (0〜127)  ]
[Bit 7 = 0 の場合]  [ 0 ][ 戦闘フラグ ][ 未使用 ][ エンカウント種別 ]
```

---

### パターンA：Bit 7 が `1` の場合（テレポート先タイルの場合）

街・城・洞窟などの「入り口」となるタイルです。

|    ビット    | マスク値 | 役割                                                              |
| :----------: | :------: | :---------------------------------------------------------------- |
|  **Bit 7**   |  `0x80`  | **テレポート有効フラグ**（`1` でテレポートマス）                  |
| **Bit 0〜6** |  `0x7F`  | **テレポート先ID**（0〜127：`ONTELEPORT` テーブルのインデックス） |

* **動作：**
  * このマスを踏むと指定したIDの街やダンジョン内部へ画面が切り替わります（コーネリアの街、カオス神殿など）。
  * テレポートタイルの場合、**戦闘エンカウントは強制的に発生しません**（`m_fight_none` が有効になります）。

---

### パターンB：Bit 7 が `0` の場合（通常フィールドタイルの場合）

テレポート先ではない通常のタイルでは、戦闘が発生するかどうか、およびどの敵グループ（テーブル）を参照するかを定義します。

|    ビット    | マスク値 | 属性名           | 意味                                                                                 |
| :----------: | :------: | :--------------- | :----------------------------------------------------------------------------------- |
|  **Bit 7**   |  `0x80`  | テレポートフラグ | `0`（通常タイル）                                                                    |
|  **Bit 6**   |  `0x40`  | 戦闘発生フラグ   | `0`：**エンカウントなし**（安全地帯）<br>`1`：**エンカウントあり**（戦闘が発生する） |
| **Bit 2〜5** |  `0x3C`  | 未使用           | 通常は `0`                                                                           |
| **Bit 0〜1** |  `0x03`  | エンカウント種別 | どの敵テーブルを参照するかを決定（下記参照）                                         |

#### 戦闘発生時の組み合わせ（`data[1] & 0x43` の値）
コード内の判定式 `temp = data[1] & 0x43;` に対応する動作です。

* **`0x00` 付近 ( `temp < 0x40` )：エンカウントなし**
  * 街の直前マスや橋の上など、敵が出現しない安全地帯。
* **`0x40`：通常エンカウント（陸上）**
  * 平地・森・山・砂漠など、地上の敵テーブルを参照して戦闘が発生。
* **`0x41`（または `0x43`）：川エンカウント（カヌー）**
  * 川をカヌーで移動中に出現する敵テーブルを参照（ピラニアやクロコダイルなど）。
* **`0x42`：海洋エンカウント（船・外海）**
  * 船で移動中に出現する海の敵テーブルを参照（サハギンやサメ、海賊など）。

# 地名

ファミコン版『FF1』のROM内部には、**タイルIDに対して直接「コーネリア」「カオス神殿」といった「地名文字列（テキスト）」が紐づくデータ構造は存在しません。**

そもそもファミコン版FF1には「街に入ったときに画面上に地名が表示される」という機能自体がなく、地名はNPCの会話メッセージ等の中にしか存在しません。

ただし、**「そのタイルを踏むと、どのマップ（街・城・ダンジョン）に移動するか」という行き先情報**は厳密にプログラムとデータテーブルで管理されています。エディタ（FFHackster）に表示される地名は、この行き先マップを元にエディタ側が分かりやすくラベル（名前）を付けたものです。

この仕組みと、実際に存在する地名（行き先）の対応関係を解説します。

---

### 1. タイルと地名（行き先）が結びつく仕組み

前回解説した `data[1]`（属性2バイト目）から、以下の3段階のステップで行き先のマップが決定されます。

```
[ ワールドマップのタイルID (0〜127) ]
        ↓
  `data[1]` の Bit 7 が 1（テレポートタイル）なら、
  下位ビットが「テレポート先ID（0〜31）」を指す
        ↓
[ ONTELEPORT テーブル (ROMオフセット 0x2C10 / 全32個) ]
  各エントリ（3バイト）：
  ・遷移先マップID（標準マップ 0〜60）
  ・出現座標X
  ・出現座標Y
        ↓
[ 実際のマップ（コーネリアの街、カオス神殿1Fなど） ]
```

* **FFHacksterのコードとの対応：**
  `OverworldMap.cpp` にある以下のコードがこの処理を行っています。

  ```cpp
  // タイル属性からテレポート先ID（0〜31）を取り出してコンボボックスにセット
  m_teleportbox.SetCurSel(data[1] - 0x80);
  
  // コンボボックスの選択肢（地名一覧）を読み込む
  LoadCombo(m_teleportbox, LoadONTeleportLabels(*cart));
  ```

  ここで呼ばれている `LoadONTeleportLabels` が、テレポート先ID（0〜31）に対して「Coneria」「Temple of Fiends」などの地名ラベルを割り当てています。

---

### 2. タイルIDと地名の関係（タイルの使い回しができない理由）

『FF1』のオーバーワールドには **128種類（`0x00`〜`0x7F`）** のタイルがあります。

各タイルの属性（`data[1]`）にテレポート先IDが直接書き込まれているため、**「同じグラフィックの洞窟アイコンでも、行き先が違うなら別のタイルIDを用意しなければならない」**という制約があります。

* 例：「マトーヤの洞窟」と「アースの洞窟」は見た目が同じ洞窟の穴グラフィックですが、**内部的にはそれぞれ別のタイルID**が割り当てられています（片方はマトーヤの洞窟へのテレポートID、もう片方はアースの洞窟へのテレポートIDが設定されているため）。
* そのため、128個のタイルIDの中には実質的に**「コーネリア専用タイル」「カオス神殿専用タイル」**のように特定の地名専用となっているタイルが多数存在します。

---

### 4. テレポートIDを使わない特殊な地名・施設

マップ切り替え（テレポート）を行わないため、上記の32枠に含まれず **`data[0]`（1バイト目）のイベントビット** で直接処理される特別な地名（施設）もあります。

1. **キャラバン（リュカーン砂漠のオアシス）**
   * `data[0] & 0xC0 == 0x80`
   * 別マップに切り替わるのではなく、フィールド画面のまま直接「妖精のビン」を売る商人のウィンドウが開きます。
2. **飛空艇浮上ポイント（リュカーン砂漠南）**
   * `data[0] & 0xC0 == 0xC0`
   * 「ふゆうせき」を持っていると飛空艇が浮上するイベントが発生します。

| イベント種別         | 名称                       | 判定方法                 | 対応するタイルID |
| :------------------- | :------------------------- | :----------------------- | :--------------: |
| **ショップ・会話**   | **キャラバン（オアシス）** | `data[0] & 0xC0 == 0x80` |      `0x36`      |
| **オブジェクト出現** | **飛空艇浮上ポイント**     | `data[0] & 0xC0 == 0xC0` |      `0x37`      |

// ③ 生成処理
function generateTileEventList(dump, teleports) {
    const bytes = dump.trim().split(/\s+/).map(h => parseInt(h, 16));
    const totalTiles = bytes.length / 2;
    const tileEventList = {};

    for (let tileId = 0; tileId < totalTiles; tileId++) {
        const data0 = bytes[tileId * 2];
        const data1 = bytes[tileId * 2 + 1];

        // テレポート判定 (data[1] の Bit 7)
        if ((data1 & 0x80) !== 0) {
            const teleId = data1 & 0x7F;
            tileEventList[tileId] = teleports[teleId];
        }
        // 特殊施設・イベント判定 (data[0] の Bit 6・7)
        else if ((data0 & 0xC0) === 0x80) {
            tileEventList[tileId] = "キャラバン（オアシス）";
        } else if ((data0 & 0xC0) === 0xC0) {
            tileEventList[tileId] = "飛空艇浮上ポイント";
        }
    }

    return tileEventList;
}
