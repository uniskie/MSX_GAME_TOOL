# ハイドライド3 MSX1版/MSX2版 用ツール

``` basic
RUN "HYDLIDE3.BAS"⏎
```

で実行。

## ファイル

- `HYDLIDE3.BAS`   ...本ツール
- `HYDLIDE3.BIN`   ...マシン語ファイル `0xA000` にロードされる
- `HYD3-EXP.BIN`   ...マシン語ファイル `0xF975` にロードされる
- `*.HD3`          ...キャラクターセーブデータファイル（4人分）
- `*.H3B`          ...MSX1版状態セーブファイル（RAM+VRAM）
- `*.H3M`          ...MSX2版状態セーブファイル（RAM）
- `*.H3V`          ...MSX2版状態セーブファイル（VRAM）
- `HYD3CHAR.BAS`   ...キャラクターデータ改造ツール

※ H3Vは128KB以上あるので、2DDフロッピーをかなり圧迫する。

## 対応機種

- MSX/MSX2/MSX2+/MSXturboR
- MSX-DOS/MSX-DOS2対応
- 要:RAM64KB以上（メモリマッパ不要）
- ※MSX2版の場合はMSX2以上 VRAM128KB以上

## 機能

※ ターボR/DOS2対応。  
※ ターボRの場合、ツール処理はR800、ゲーム中はZ80で動作。

- **[G] PLAY GAME**

  新規ゲームを実行する。  
  セーブデータの領域を使う。

  > **HYD3CHAR.BAS** でデータを編集した後は CONTINUE を避け、  
  > **[G]** で**新規ゲーム開始**を。

- **[C] CONTINUE GAME**  
  ※ 諸注意アリ

  中断データがあれば、中断したところから再開する。

  - **※【注意】** → **場面によっては安定しない**可能性がある。
  - **※【注意】** → MSX1と2、異なる**機種をまたぐことはできない。**
  - ※ **MSX2版**はカラーパレットやVDPの状態を復元するために  
    一度Bボタン（RETURNキー）で**メニューを開くと良い。**
  - ※ **再開**の場合、**表RAM** `0C000H` のセーブデータは**破棄**され、  
    **裏RAM**に保存された**中断データエリアのセーブデータが使用される。**
  - ※ 中断データの存在チェックは甘いので、  
    再起動や他のプログラムで部分的に破壊されていても、  
    メモリ内にヘッダが存在すると**誤判定**される事がある。

- **[M] FORCE CAMP NOW**

  プレイ中断中の状態を**強制的にセーブデータ領域に書き込む。**  
  現在位置でキャンプしたのと同じ扱いになる。  
  （※ 回復はしない）

  **実質的に一番安全な状態セーブ**として使用できる。

  （MSX1版の状態をMSX2版で再開できる。その逆も可能。）

- **[L] LOAD CHARACTERS**

  セーブデータ（`*.HD3`、4人分）をディスクから読み込む。  
  そのあと、ゲームを新規実行する。

- **[S] SAVE CHARACTERS**

  セーブデータ（`*.HD3`、4人分）をディスクに保存する。

- **[R] STATE LOAD**  
  **※【非推奨】→ 安定しない**ケースがある。

  中断データをディスクから読み込み、  
  ゲームを中断箇所から再開する。

- **[W] STATE SAVE**  
  **※【非推奨】→ 安定しない**ケースがある。

  中断データをディスクに保存する。

- **[P] COLOR:MSX2/MSX1**

  （MSX1版の場合）MSX1風パレットに切り替える。

- **[E] CHARA DATA EDIT**

  キャラクターデータ改造ツール（`HYD3CHAR.BAS`）を起動する。

## 拡張ポーズ（ゲーム中）

### [STOP]キーで拡張ポーズ

エミュレータの[STOP]キー割り当て

- BlueMSX : **[PageUp]**
- openMSX : **[F8]**
- 1chipMSX : **[End]**

### 拡張ポーズ中（capsランプ点滅）

- **[STOP]**       ...ゲームに戻る。
- **[CTRL+@]**     ...ゲームを中断してBASICに戻る（**状態は保存される**）
- **[CTRL+HOME]**  ...ゲームをソフトリセットする。
- **[CTRL+F5]**    ...エンディングを強制実行する。（**タイトルデモ中は危険**）  
  （※ サウンドテストにエンディングが含まれない為、追加）

### CTRL+@でBASICに戻った後

- BASICに戻った後 **[C] CONTINUE** で中断した状態から再開できる。
- BASICに戻って **[M]** を押して強制セーブした場合は、  
  **[G] PLAY GAME** で開始して、セーブデータをロード開始する事。
- **[W]** で中断状態をファイルへ保存。  
  **[R]** でファイルに保存した中断データから再開。
- **[S]** でセーブデータをファイルへ保存。（FMPAC/PACやテープの代わり）  
  **[L]** でセーブデータをファイルから読み込む。

## 状態セーブロード機能

- ゲームを中断してBASICへ戻り、再開する機能

- ディスクへの状態丸ごとセーブロード  
  ※注）SCREEN0以外に切り替えるとVRAM状態が復帰不能

- MSX1版は安定

- MSX2版は共通パレットのみ復元  
  → ゲーム中のMulti-Windowメニュー（[RETURN]またはトリガ2で開くもの）を閉じる時に  
  パレットが復元される。

- ゲーム中以外の保存が不安定。  
  タイトルデモ/エンディングへの復帰は画面がおかしくなり、暴走の可能性あり。

- 1chipMSXのクロックアップモードでMSX2版を動かしている場合、  
  しばらくすると暴走する模様。  
  このツールが原因かどうかは不明（VDP操作に失敗する？）

その他詳細は後述します。

## キャラクターデータ改造ツール

ゲーム中のRAMのワークエリアを書き換えるものなので、一度ゲームを実行してからRAMの状態を維持してBASICに戻る必要があります。

- ※ 重いのでターボR推奨

### 手順

1. （あれば）PAC/FMPACを挿し、**ハイドライド3のカートリッジは挿さず**にMSX本体の電源投入
2. `RUN"HYDLIDE3.BAS"` でハイドライド3起動ツールを実行。
3. ツールが起動したらカートリッジを後挿しする。
4. **[L] LOAD CHARACTERS** または **[G] PLAY GAME**  
   ゲーム開始後、**[STOP]**→**[CTRL+@]**  
   （ゲームを中断してツールに復帰）
5. **[E] CHARA DATA EDIT** でキャラクターエディタ開始。
6. **[CTRL+STOP]** でキャラクターエディタ終了（チェックサム更新後、自動で `HYDLIDE3.BAS` が再起動する）。
7. （自動で戻らない場合のみ）`RUN"HYDLIDE3.BAS"` でハイドライド3起動ツールに戻る。
8. **[G] PLAY GAME** または、  
   **[S] SAVE CHARACTERS** → **[L] LOAD CHARACTERS**  
   で、ゲーム開始。

   - ※ **CONTINUE**の場合、編集したセーブデータは破棄されます。

   - ※ 編集したらセーブ推奨。  
     `"HYDLIDE3.BAS"` ツールを起動したときに、  
     **[C] CONTINUE GAME** が表示されている場合は、  
     **[S] SAVE CHARACTERS** でデータセーブをし、  
     **[L] LOAD CHARACTERS** でデータロード開始。

> フリーエリアが足りなくて読み込めない場合は  
> `CLEAR 200,&HBEFF:RUN"HYD3CHAR.BAS"`

機能の詳細は後述します。

### 注意事項

キャラクタデータの改造はRAM上のキャラクタデータワークエリアを変更するだけなので、  
PAC/FMPACのSRAMは変更されません。

**[S] SAVE CHARACTERS** して **[L] LOAD CHARACTERS** する（または **[G] PLAY GAME** で新規開始する）ことで、PACのSRAMにも保存されます。

> **【警告】**  
>
> **[C] CONTINUE GAME** や **[R] STATE LOAD** では、  
> 編集したキャラクターデータはゲームに反映されず、**編集した内容が失われます。**

### キャラクターデータのアドレス

``` text
address: 0xC000
size:    0x400
保存キャラクターデータの受け渡しバッファ（4キャラ分）
```

ここを読み書きしてツール（`HYDLIDE3.BAS`）に渡すと  
キャラクターデータが書き換わります。  
（チェックサムを調べて合っていれば取り込み）

### チェックサム計算

1キャラ256バイトで、最後の1バイトはチェックサム。

チェックサムの計算式は `(+0x0000)`～`(+0x00FE)` の合計 `+ 0x4A`

``` basic
CLEAR 200,&HBEFF
A$="FE02C02AF8F706FFAF862310FCC64A6F260022F8F7C9"
FOR I=1TO LEN(A$)-1 STEP 2:POKE &HBF00+I\2,VAL("&H"+MID$(A$,I,2))
PRINT".";:NEXT:DEFUSR5=&HBF00
A=USR5(データアドレス)
```

または

``` basic
CLEAR 200,&HA000
BLOAD"HYDLIDE3.BIN":DEFUSR5=&HA000+15
A=USR5(データアドレス)
```

で、チェックサムの計算結果が取得可能です。

## MSX2版：「中断・再開」機能について補足

VDPアクセスにBIOSを使用していないプログラムの場合は、パレットの値を後から取得する方法がありません。  
そのため、再開時はメニュー画面用パレットで再開しています。

よってMSX2版では、以下のような注意点や制限があります。

- **注意点**
  - なるべくメニュー画面で中断する。（パレットが固定）
  - フェードアウト中に中断・再開をしない。（パレットが不定なので再現困難）
  - ED/OPで中断・再開をしない。（非対応）

- **強制的にパレットを正常化する方法**
  - メニューを開いて閉じる
  - マップ切り替えをする

- **メーカーロゴ画面に対応していない**
  - 一時的にSCREEN5になっている：非対応。
  - パレットアニメーションの復帰に対応していない。  
    → 将来的に判定できれば対応可能かもしれない（現状未対応）

- **タイトルデモのパレット2倍表示に対応していない**
  - パレットの復帰に対応していない
  - HSYNC割り込みの状態を保存復帰できない。  
    → 将来的に判定できれば対応可能かもしれない（現状未対応）

- **エンディングアニメーション時の画面に対応していない**
  - 一時的にSCREEN5になっている：非対応。
  - パレットの復帰に対応していない。  
    → 将来的に判定できれば対応可能かもしれない（現状未対応）

- **ディスクの読み書きが遅い。**
  - VRAM 128KBを読み書きするため遅い。
  - バッファが `0x2000` しかないのでさらに遅い。
  - 裏RAM `0x6000-0x7FFF` が空いているがディスクアクセス中は使いづらい。

### MSX2版ステートロード時のカラーパレット

ハイドライド3はVDPを直接アクセスしているため、パレットは読み出せませんので、  
本ツールでは、MSX2版ゲーム再開時のパレットを決め打ちにしています。

``` basic
マップ共通パレット（UIのみ）
A$="000000000537000056163750000000000754015610777000" 'MSX2PAL(COMMON)
```

``` basic
昼の街のパレット
A$="567455430537541056163750153432222754015610777000" 'MSX2PAL(TOWN/NOON)
```

### （調査）ゲーム中の状態を解析してパレット設定ルーチンを呼び出す事自体は可能？

``` text
タイトル        $00,$01,$06,$07
エンディング    $00,$01,$06,$07
トップメニュー  $0A,$0B,$08,$0F
ゲームメニュー  $09,$0A,$08,$0F
```

> ※ `$0000` はアセンブラでの16進数表記の一つ。C言語等の `0x0000` に相当する。

→ 結果：Bank番号だけでは識別できない様子

現在の表示モード（OP/ED/MAP/SHOP/MENU）とマップ番号のワークエリアが分かれば判定は可能かもしれませんが、OP/EDは呼び出し先だけ異なる可能性が高いので少し面倒くさそうですね。

# おまけ：キャラクターデータエディタ 詳細解説

``` basic
RUN "HYD3CHAR.BAS"⏎
```

- 重いのでターボR推奨
- 編集したらセーブ推奨
- 編集した後に `"HYDLIDE3.BAS"` ツールを起動
  - **[C] CONTINUE GAME** が表示されている場合は、
  - **[S] SAVE CHARACTERS** でデータセーブをして
  - **[L] LOAD CHARACTERS** でデータロード開始
  で、編集したパラメータで遊べる。

  （CONTINUEの場合、編集したセーブデータは破棄されてしまう）

`HYDLIDE3.BAS` 実行後だとフリーエリアが足りなくて読み込めない場合があるので、その場合は

``` basic
CLEAR 200,&HBEFF:RUN"HYD3CHAR.BAS"
```

で実行すると良い。

## 操作

メイン

- **移動**：**カーソル**キー
- **選択/決定**：**RETURN**キー、**SPACE**キー
- **キャンセル**：**ESC**キー
- **キャラ変更**：`No.？`にカーソルを合わせて**BS**キーまたは**SPACE**キー（**BS**キーの場合は逆順）
- **数値**：そのまま数字入力で新規入力、**左右**キーで移動した場合は既存値の編集
- **文字編集**：ひらがな、カタカナ、英数字、**DEL**キー、**BS**キー、**左右**キー

アイテムの編集

- **移動**：**カーソル**キー
- **アイテムの選択/決定**：**RETURN**キー
- **キャンセル/戻る**：**ESC**キー
- **使用状態**：**SPACE**キー
- **所持数**：**「N」**キー

### HYDLIDE3.ASM : Bankの識別

`"HYDLIDE3.BAS"` で、ロム認識後のコマンド受付時、  
**[?]**（`[SHIFT]+[/]`）でBank特定用ハッシュをテキスト出力。  
（`IDDTBL`、`IDDCHK` の内容）

- `HYD3M1ID.TXT`    ... MSX1版の場合
- `HYD3M2ID.TXT`    ... MSX2版の場合

ハイドライド3はワークエリアを使用せず直接Bank切り替えするケースがあり、  
現在のBank選択状態を知る方法は「現在のメモリの状態を調べる」事になる。

全比較では遅くなるため、ハッシュテーブルを作成して比較している。  
（※ 先頭8バイトが `0` 等で埋まっているバンクでの誤判定を避けるため、各バンク `+0008H` 位置から `$400H` おきに6バイトを採取している）

空のBank以外は特定ハッシュ値が重複するとまずいため、  
チェック用にテキスト出力機能を隠し機能として用意。

（※ 自動的な重複エラー報告機能は追加していない。目視で確認する）

## HYDLIDE3.ASM と HYD3-EXP.ASM のやりとり

### ゲーム中の `$C000`-`$FFFB` 領域

BASIC時は裏RAM `$0000`-`$3FFB` に置かれる。  
（ゲーム実行時に入れ替わる）  
（裏RAM入れ替え時、16BIT値のチェックサムを計算し `$3FFC` に格納）

ゲーム時の `$C000`-`$FFFB` の内容（BASIC時の裏RAM `$0000`-`$3FFB`）は  
状態セーブロード時に読み書きされる。  
（ほかにはVRAMデータも読み書きされる）

### ゲーム拡張割り込み処理 スタックエリア

BASIC PLAY文用のキュー管理ワーク（`VCBA-VCBB`）を利用する（SP初期値は `VCBC` = `$FB8B`）。

``` text
    $FB41,74    (VCBA-VCBB)    ※スタック下限: $FB41 (VCBA)
```

※ なお、ゲーム側のスタックポインタ退避には `SAVSP`（`$FB36`, 2バイト）を使用している。

### ゲーム拡張割り込み処理 ワークエリア

BASIC PLAY文用のキュー管理ワーク（`VCBC`）を利用する。

``` text
    $FB8B,37    (VCBC)
                + 0, 1  BANK_0  ROM Bank 0 のBank番号（ページ0）
                + 1, 1  BANK_1  ROM Bank 1 のBank番号（ページ1）
                + 2, 1  BANK_2  ROM Bank 2 のBank番号（ページ2）
                + 3, 1  BANK_3  ROM Bank 3 のBank番号（ページ3）
                + 4, 2  BASVER  HYDLIDE3.ASM のバージョン（中断データ検査用）
                + 6, 2  EXPVER  HYD3-EXP.ASM のバージョン（中断データ検査用）
                + 8, 1  MSXVER  ROMのMSXバージョン（中断データ検査用）
                + 9, 3  （空き）
                +12, 1  CAPSTA  CAPSランプ状態（点滅用）
                +13, 7  （空き）
                +20, 2  EXPSP   HYD3-EXP拡張割り込み時のスタックポインタアドレス（再開用）
                +22, 1  （空き）
                +23,13  PSG_SV  PSGレジスタ#0-#12保存用
                +36, 1  （空き）（PSGレジスタ#13用予約）
```

### ゲーム拡張割り込みプログラム

BASIC PLAY文用のキューバッファ（`VOICAQ - VOICCQ`）を利用する。

``` text
    $F975,$180  (VOICAQ - VOICCQ)
            +0,2    DW VERSION  バージョン番号
            +2,2    DW EXPSIZ   HYD3-EXPのプログラムサイズ
            +4,2    DW EX_TRAP  割り込み処理アドレス
            +6,2    DW SET_UP   新規ゲーム開始処理アドレス
            +8,2    DW CONTINUE ゲーム再開処理アドレス
            （以降、プログラム本体）
```

- **中断時**：拡張割り込みモードから `HYDLIDE3` に処理を戻す。  
  `GAMVER`：ROMタイプ（`0`:なし、`1`:MSX1版、`2`:MSX2版）  
  `(SAVVER)` と `(MSXVER)` に状態データタイプ（`0`:なし、`1`:MSX1版、`2`:MSX2版）  
  （`MSXVER` は保存データ側に格納されている値）  
  （`SAVVER` は `HYD3STRT`（`HYDLIDE3.ASM`）側に格納されている値）

- **`HYD3_CHK`**：HYDLIDE3が刺さっているか調べる

  刺さっていれば、
  1. MSX1版かMSX2版か調べる
  2. `ROMSLT` に検出したスロット番号を書き込む
  3. メガROM Bank特定用データを作成する
  4. `MSXVER` 含めて状態保存データのバージョンを調べる

  バージョンが合っていれば `SAVVER` を `MSXVER` の値で上書きする。

  返り値は、`0`=なし、`1`=MSX1版、`2`=MSX2版  
  `(ROMSLT)` にスロット番号

- **保存時**：`SAVVER`（`MSXVER`）に合わせて保存処理を実行  
  （保存前にMSX1版とMSX2版ロムが入れ替わっていても大丈夫）

- **再開時**：再開条件
  1. `(GAMVER == SAVVER) && (GAMVER > 0)`
  2. RAMページ3とVRAMが維持されている  
     （RAMページ0のチェックサムも判定）  
     （RAMページ0：ゲーム時のRAMページ3退避用、  
       RAMページ1：ゲーム時のVRAM先頭 `2000H` 一時退避用）
  3. 保存されていたゲーム時RAMページ3の `BASVER`、`EXPVER` が正しい場合、  
     保存されていたRAMページ3とBASIC時のRAMページ3を入れ替え
  4. 中断時のROM Bankを復帰し、  
     拡張ポーズモードから再開

  ※ VRAM全体の破壊チェックはしていないのでVRAMを破壊しないように要注意

### システム文字列

Bank: `$28`～`$29` (ROM `$50000`-`$53FFF`)

- 文字列ID: `$0` ～ `$147`

- MEMアドレス -> ROMアドレス 変換式  
  `(MEM_ADDR - 0x4000 + 0x50000) = ROM_ADDR`

## スプライトパターン

### MSX1版

- **仕様:** 1キャラ当たり `32 byte * 2枚` でセット（武器系は1枚）

| データ内容               | 開始ｱﾄﾞﾚｽ | 終了ｱﾄﾞﾚｽ | 開始Bank + OFFSET  | 終了Bank + OFFSET  |
| :----------------------- | :-------- | :-------- | :----------------- | :----------------- |
| 街キャラスプライト       | `$20000`  | `$20EFF`  | `Bank $10`+`$0000` | `Bank $10`+`$0EFF` |
| 敵キャラスプライト       | `$20F00`  | `$277FF`  | `Bank $10`+`$0F00` | `Bank $13`+`$17FF` |
| 敵キャラ武器スプライト   | `$28000`  | `$28C6F`  | `Bank $14`+`$0000` | `Bank $14`+`$0C6F` |
| 妖精スプライト           | `$11103`  | `$111C2`  | `Bank $08`+`$1103` | `Bank $08`+`$11C2` |
| プレイヤースプライト     | `$48000`  | `$49AFF`  | `Bank $24`+`$0000` | `Bank $24`+`$1AFF` |
| プレイヤー武器スプライト | `$49B00`  | `$49FEF`  | `Bank $24`+`$1B00` | `Bank $24`+`$1FEF` |
