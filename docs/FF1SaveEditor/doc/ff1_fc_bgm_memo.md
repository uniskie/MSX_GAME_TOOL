## 初めに

NESファイルアドレスはiNESヘッダ16バイト（0x10）を含み、FC ROMアドレスはヘッダを含まないPRG-ROM内の物理位置を示します。


## マップとBGMの関係

1. 各通常マップのヘッダデータに、マップの形状・グラフィックを定義するタイルセット番号（Tileset ID: 0〜7）が指定されています。
2. Bank 0x0F（NESファイル 0x3CFE3 / FC ROM 0x3CFD3 / CPU 0xCFD3）のルックアップテーブルを参照し、「タイルセット番号 → BGM ID」へと変換されてサウンドドライバに送られます。
3. ワールドマップ（地上）は通常マップとは別の独立ルーチンで制御され、乗り物フラグ等によってBGM（徒歩・船・飛空艇）が切り替わります。

※曲名と使用ダンジョンの不一致について:  
公式サントラで「海底神殿」と題されている楽曲（BGM ID: 0x4E）は、ゲーム中のダンジョン「海底神殿」では流れず、ラストダンジョン「過去のカオスの神殿」で演奏されます。
逆に、ダンジョン「海底神殿」で流れるのは「カオスの神殿」（BGM ID: 0x4C）です。

## 通常マップ（町・城・ダンジョン各フロア 全61マップ）

### タイルセットとBGMの対応テーブル

通常マップに適用されるタイルセット番号（0〜7）と、そこから再生されるBGMの定義テーブルです。固定バンク（Bank 0x0F）内に配置されています。

- NESファイル: 0x3CFE3 〜 0x3CFEA
- FC ROM: 0x3CFD3 〜 0x3CFDA
- CPUアドレス: 0xCFD3 〜 0xCFDA（Bank 0x0F 常駐領域）
- データサイズ: 8 バイト

```text
インデックス:  0   1   2   3   4   5   6   7   (タイルセットID)
バイナリ値  : 47  48  49  4A  4B  4C  4D  4E  (BGM ID)
```

| タイルセットID | タイプ       | BGM ID | 演奏される楽曲名 |
| :------------: | :----------- | :----: | :--------------- |
|       0        | 町系         |  0x47  | 街               |
|       1        | 城系         |  0x48  | コーネリア城     |
|       2        | 地底・火山系 |  0x49  | グルグ火山       |
|       3        | 洞窟系       |  0x4A  | マトーヤの洞窟   |
|       4        | 遺跡・塔系   |  0x4B  | ダンジョン       |
|       5        | 神殿・水系   |  0x4C  | カオスの神殿     |
|       6        | 空中城系     |  0x4D  | 浮遊城           |
|       7        | 過去神殿系   |  0x4E  | 海底神殿         |

### サブマップの基本構造とメモリレイアウト

- マップ総数: 61マップ（マップID: 0x00 〜 0x3C）
- マップサイズ: 全マップ共通 64 × 64 メタタイル（計 4,096 タイル）
- 1メタタイルの定義: 16×16 ピクセル（8×8ピクセルのCHRキャラクタ4枚で構成）
- 格納バンク:
  - Bank 0x04（FC ROM 0x10000〜0x13FFF / NESファイル 0x10010〜0x1400F）
  - Bank 0x05（FC ROM 0x14000〜0x17FFF / NESファイル 0x14010〜0x1800F）
  - マップ圧縮データ、オブジェクト配置、テレポート定義等が Bank 4〜5 に配置されています。
- 固定バンク（Bank 0x0F: FC ROM 0x3C000〜0x3FFFF）:
  - タイルセット別BGM変換テーブル（FC ROM 0x3CFD3 / NESファイル 0x3CFE3）等が存在します。

### テレポートおよびタイルセットデータの構造

テレポート関連データは、エントリ単位の構造体ではなく、座標やマップIDを項目ごとのプレーンに分けた平行配列（SoA方式）で格納されています。同一のインデックス（0から始まる通し番号）を用いて各配列を並列に読み出します。

#### 地上進入テレポート（フィールド → 通常マップ）

フィールド上の拠点32箇所の進入先データです。

- X座標テーブル: NESファイル 0x02C10 / FC ROM 0x02C00 / CPU 0xAC00（32 bytes）
- Y座標テーブル: NESファイル 0x02C30 / FC ROM 0x02C20 / CPU 0xAC20（32 bytes）
- マップIDテーブル: NESファイル 0x02C50 / FC ROM 0x02C40 / CPU 0xAC40（32 bytes）
- 構成: 32エントリ。各テーブルの同一インデックスを参照し、転送先マップID、出現X座標（0〜63）、出現Y座標（0〜63）を取得します。

#### 地上脱出テレポート（通常マップ → フィールド）

ダンジョンから外へ出る、または「テレポ」使用時の地上脱出先データです。

- ワールドX座標テーブル: NESファイル 0x02C70 / FC ROM 0x02C60 / CPU 0xAC60（16 bytes）
- ワールドY座標テーブル: NESファイル 0x02C80 / FC ROM 0x02C70 / CPU 0xAC70（16 bytes）
- 構成: 16エントリ。インデックス0〜8の計9件が有効で、残りは00埋めされています。
  - 0: 巨人の洞窟（東出口）
  - 1: 巨人の洞窟（西出口）
  - 2: 氷の洞窟
  - 3: 試練の城
  - 4: コーネリア城
  - 5: アースの洞窟
  - 6: グルグ火山
  - 7: 海底神殿
  - 8: 浮遊城

#### マップ別タイルセット指定（タイルセットID）

各通常マップで使用するグラフィック・属性セットの指定データです。

- 格納アドレス: NESファイル 0x02CD0 / FC ROM 0x02CC0 / CPU 0xACC0（61 bytes）
- 構成: 61エントリ。マップID 0x00（コーネリア）から 0x3C（巨人の洞窟）までのタイルセット番号（0〜7）が順に1バイトずつ格納されています。

#### マップ間テレポート（通常マップ間の移動・階段・ワープ）

ダンジョン内の階段、落とし穴、扉、ワープゾーン全64箇所のデータです。

- X座標テーブル: NESファイル 0x02D10 / FC ROM 0x02D00 / CPU 0xAD00（64 bytes）
- Y座標テーブル: NESファイル 0x02D50 / FC ROM 0x02D40 / CPU 0xAD40（64 bytes）
- マップIDテーブル: NESファイル 0x02D90 / FC ROM 0x02D80 / CPU 0xAD80（64 bytes）
- 構成: 64エントリ。各テーブルの同一インデックスを参照し、転送先フロアのマップID、出現X座標（0〜63）、出現Y座標（0〜63）を取得します。各マップデータ内のテレポートトリガーから参照インデックスが指定されます。

### タイルセットとメタタイル構築定義（TSA）

サブマップのグラフィックは8種類のタイルセット（0〜7）で管理されます。各タイルセットは128個のメタタイル（ID 0x00〜0x7F）を持ちます。

1つのメタタイル（16×16ピクセル）は、4枚の8×8 CHRタイル番号とパレット指定（2ビット）で構成されます。ROM上では Bank 00（NESファイル 0x00810 / FC ROM 0x00800 / CPU 0x8800）に 4096バイト（8セット×128個×4枚）で格納されています。ゲーム実行時、選択されたタイルセットのデータが以下のRAMアドレス（0x0500〜0x077F）に展開されます。

| RAM アドレス     |  サイズ   | 役割・データ内容                                        |
| :--------------- | :-------: | :------------------------------------------------------ |
| 0x0500 〜 0x057F | 128 bytes | 各メタタイル（0x00〜0x7F）の左上 8×8 CHRタイルID       |
| 0x0580 〜 0x05FF | 128 bytes | 各メタタイル（0x00〜0x7F）の右上 8×8 CHRタイルID       |
| 0x0600 〜 0x067F | 128 bytes | 各メタタイル（0x00〜0x7F）の左下 8×8 CHRタイルID       |
| 0x0680 〜 0x06FF | 128 bytes | 各メタタイル（0x00〜0x7F）の右下 8×8 CHRタイルID       |
| 0x0700 〜 0x077F | 128 bytes | 各メタタイルのパレット属性（下位2ビット: パレット0〜3） |

### タイル属性テーブル（当たり判定・動作制御）

各タイルセットごとに128バイト（メタタイル 0x00〜0x7F に1対1対応）の属性テーブルが存在します。ROM上では Bank 00（NESファイル 0x01810 / FC ROM 0x01800 / CPU 0x9800）に計 1024バイト（8セット×128B）で格納されています。通行可否や踏んだ際の挙動を制御します。

```text
 Bit:   7   6   5   4   3   2   1   0
       [S] [D] [H] [T] [C] [B] [P] [M]
```

- Bit 0 (M): 通行不可フラグ（0=通行可、1=進入不可）。
- Bit 1 (P): カヌー・水路フラグ。
- Bit 2 (B): 固定エンカウント（玄室マス）。踏むと強制戦闘が発生。
- Bit 3 (C): 宝箱フラグ。調べると宝箱開封ルーチンが実行される。
- Bit 4 (T): 出口・階段フラグ。踏むとテレポートルーチンが発動。
- Bit 5 (H): ダメージ床（溶岩・毒沼）。1歩ごとにHPが1減少。
- Bit 6 (D): 扉タイル。踏むと部屋の内外フラグ（RAM 0x000D）を反転。
- Bit 7 (S): 会話・NPC・ショップカウンターなどのイベント接触トリガー。

### オブジェクト・キャラクター配置テーブル

各サブマップに配置されるNPCや固定シンボル（町人、王、バハムート、クリスタル等）のデータです。マップごとにオブジェクト数分のエントリが並び、終端コード（0xFF）で区切られます。

| オフセット | フィールド名 | 内容                                   |
| :--------: | :----------- | :------------------------------------- |
|     +0     | X 座標       | マップ上の初期X座標（0〜63）           |
|     +1     | Y 座標       | マップ上の初期Y座標（0〜63）           |
|     +2     | スプライトID | キャラクタのグラフィックID             |
|     +3     | 動作フラグ   | 移動パターンおよび配置状態（下記参照） |

- 動作フラグ（Byte 3）の仕様:
  - Bit 0〜3: 移動パターン（0=静止、1=ランダム歩行、2=往復等）
  - Bit 4: 部屋内配置フラグ（部屋の外にいる間はスプライト非表示）
  - Bit 5〜7: 初期向き（上・下・左・右）またはイベントフラグ

### 圧縮マップデータの構造

64×64（4,096タイル）のサブマップデータは、容量削減のためランレングス形式の可変長圧縮で格納されています。マップの左上（0, 0）から右下（63, 63）に向かって順に展開されます。

- 連続タイル（Run-Length）: 制御バイト等により [連続数] + [タイルID] の形式で展開。
- 個別タイル（Direct）: 連続しないタイル列は、タイル番号（0x00〜0x7F）を直接ストリーム出力。
- 終端: 4,096タイル分が満たされるか、終了マーカーが出現すると展開を終了。
