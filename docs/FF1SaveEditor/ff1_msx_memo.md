# MSX版 ファイナルファンタジー 情報解析メモ

本ドキュメントはDSKから取り出したファイルを前提に記述している。

- DSKからのファイルの取り出し方は

  - `SayDosTool.py`
  - `SayDosTool_specification.md`

  を参照。

- PICファイル（圧縮画像ファイル）の展開方法は

  - `FFPicTool.py`
  - `FFPicTool_specification.md`

  を参照。

## ワールドマップデータ

### VEC ファイル

圧縮マップの各ライン先頭へのポインタテーブル

- `MMAP.VEC`

  ワールドマップのライン先頭ポインタ(16bit)のテーブル。

  ファミコン版の0x4000 (NESファイル 0x4010)と同一。 
  
  ファミコンでの実行時アドレスで書かれており、
  0x8000が圧縮データ先頭という前提で書かれている。

### MAPファイル

マップデータ本体。

- `MAIN.MAP`

  ワールドマップの本体データ。
  
  フィールドサイズは256×256タイル。
  
  ラインごとに圧縮されていて、
  ラインの先頭はポインタテーブル（MMAP.VEC）を参照する。

  MMAP.VECに書かれた値から0x8200を引いた値をオフセット値とする。
  
  - 参考：ファミコン版  
  
    - 0x4200 (NESファイル 0x4120) に置かれているデータ。
    - ライン先頭ポインタテーブルの値から0x4000を引いたROMアドレスを参照する。
      (NESファイルの場合は、0x3FF0を引く)

### CHR ファイル

各マップ毎の
**タイル属性** + **タイルチップ定義（キャラクタの組み合わせ）**
が格納されたファイル。

内容はファミコン版と同じ。
ただし、MSX版にはパレット割り当てテーブルは存在しない。

- `MAIN.CHR`

  ワールドマップ用タイル定義データ。
  
  ファミコン版の 0x0000（NESファイル 0x0010） と同一。

### SPR ファイル

#### スプライト最小単位

16x16 スプライトパターン 計32バイト + ラインカラーデータ 計8バイト  
= 合計 40バイトで1つのスプライトを構成。

- スプライトパターンは8x16が横に2つ並んで16x16ピクセルを表現している。
- ラインカラーは偶数行が上位4ビット、奇数行が下位4ビットにpackされている。


#### キャラクタ最小単位

スプライト3枚単位。

3枚の重ね合わせ表示で1キャラクタを表示している。

CCビットは使用しておらずカラーコードのORは使わず、単純に重ね合わせ表示をしている。

#### ファイルの内容

- `MSPR.SPR`

  フィールドで表示するスプライト。  

  - 船、飛空艇、カヌー、影、橋、海峡の並び。  
  - 船、飛空艇、カヌーは2パターンアニメ×4方向（上右下左）の8パターンずつ。

  - 参考：ファミコン版  

    - 乗り物は影、橋、海峡、空きの後に配置されている。
    - 乗り物は左右反転機能で反転するので、
      2パターンアニメ×3方向（上下左）の6パターンずつ。
  
    アドレス配置は
    
    - 影　　： 0x9C00（NESファイルは0x9C10）1個
    - 橋　　： 0x9C40（NESファイルは0x9C50）1個
    - 海峡　： 0x9C80（NESファイルは0x9C90）1個
    - 空き　： 0x9CC0（NESファイルは0x9CD0）1個
    - 船　　： 0x9D00（NESファイルは0x9D10）2*3=6個
    - 飛空艇： 0x9E80（NESファイルは0x9E90）2*3=6個
    - カヌー： 0xA000（NESファイルは0xA010）2*3=6個

  ※ ファミコン版、MSX版ともに、プレイヤーキャラとは上下の並びが異なる。

- `EXTRA.SPR`

  町やダンジョンで表示されるキャラクタ。
  
  1キャラクタあたり4パターン。  
  （上1パターン、下1パターン、左2パターンの計4パターン）
  
  此方は `MSPR.SPR` と異なり、ファミコン版の並びと完全に一致している。
  
  - 参考：ファミコン版

    0xA200～0xBFFF（NESファイルでは0xA210～0xC0FF）にデータが存在する。
  

- `EXTRA2.SPR`

   パターンデータが存在せずカラーテーブルだけが並ぶ特殊なデータ。
   
   内容は`EXTRA.SPR` のカラーと同一なので無視して良い。

### フィールド用 キャラクタ画像

`JOBS_L1.PIC` と `JOBS_L2.PIC` は、
それぞれ、クラスチェンジ前後のフィールド歩行用キャラクタデータ。

クラス毎のパターンは、
上、右、下、左の順番。
それぞれの方向にアニメ2パターンの合計8パターンが並ぶ。

クラスの順番は

- `JOBS_L1.PIC`

  - 戦士
  - 盗賊
  - モンク
  - 赤魔術師
  - 白魔術師
  - 黒魔術師

- `JOBS_L2.PIC`

  - ナイト
  - 忍者
  - スーパーモンク
  - 赤魔導士
  - 白魔導士
  - 黒魔導士

- 参考：ファミコン版

  ROM 0x9000 (NESファイルは 0x9010) から並んでいる。
  
  クラスごとのパターンは
  上1、下1、左2 の 計4パターン。
  
  クラスの並びは同じ。

### バトル敵キャラ画像の読み込み

FFSayDosToolでは`BATTLE_DATA.BIN` にまとめているが、
実際には多数の敵キャラ画像を読み込む。
大量にありすぎて全体の合計ファイル数が256を超える為、直接セクタアクセスしている物と思われる。

であれば、`battle` フォルダに
キャラごとに分けて`ENEMY_00.PIC`～`ENEMY_7F.PIC`として出力しても良い気はする。


``` ASM
; 敵キャラ画像読み込み
; in:   A=敵キャラの番号

.X8F56: ; (DSK +0x19756 / BATTLE.COM +0xF56)
 PUSH   HL             	;8F56: E5
 PUSH   IX             	;8F57: DD E5
 PUSH   IY             	;8F59: FD E5
 AND    #7F            	;8F5B: E6 7F
 SLA    A              	;8F5D: CB 27
 LD     D,#00          	;8F5F: 16 00
 LD     E,A            	;8F61: 5F
        ; 敵キャラ画像のオフセットテーブル
        ; 0x8FDF
 LD     IX,#8FDF       	;8F62: DD 21 DF 8F
 ADD    IX,DE          	;8F66: DD 19
 LD     E,(IX+#00)     	;8F68: DD 5E 00

        ; 敵キャラPIC形式画像の先頭セクタ 
        ; BATTLE_DATA.BIN    0x044C (1100)
 LD     HL,#044C       	;8F6B: 21 4C 04
 ADD    HL,DE          	;8F6E: 19

 LD     HL,#0100       	;8F7D: 21 00 01

 POP    IX             	;8F85: DD E1
 POP    HL             	;8F87: E1
 RET                   	;8F88: C9
```
