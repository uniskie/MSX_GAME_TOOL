# HAKKIN FF1 日本版ROM対応手順書

## エラー原因の分析とプロジェクト設定（.ff1d）の修正

本資料は、ファミコン（日本版）『ファイナルファンタジー』ROMを「HAKKIN FF1」で編集する際に発生するエラーの調査結果、および日本版ROMのデータ構造に合わせてプロジェクト設定ファイル（`.ff1d`）を修正する手順をまとめたものです。

- pythonスクリプト `patch_ff1d.py` で、プロジェクト設定ファイル（`.ff1d`）を書き換えて、日本版ROM用に修正出来ます。

- pythonスクリプト `ff1d_to_jp.py` で、プロジェクト設定ファイル（`.ff1d`）を書き換えて、ある程度日本語化出来ます。

---

## 1. 概要

HAKKIN FF1 で日本版ROMを読み込んだ際、初期設定（北米版基準のアドレス）のままでは以下の問題が発生します。

1. **画面の起動エラー**:
   「Armor」「Weapons」「Magic」の3画面を開こうとすると `IndexOutOfRangeException` が発生し、エディタが起動しない。
2. **データの不整合**:
   クラッシュしない画面であっても、防具の部位判定がズレる、移動中魔法（ケアル等）の設定が未割り当て（`--none--`）になる、ウィンドウ色や文字テーブルが北米版基準のままになるなどの差異が存在する。

本書では、これらの原因を整理し、日本版ROM向けに設定ファイルを適合させるための修正項目と適用手順を記述します。

---

## 2. エラー原因の分析

### 2.1 画面起動エラーの要因（Bank 0F）

Armor、Weapons、Magic の3エディタは、画面上に「各クラスのスプライトアイコン」を着色表示する共通処理を持っています（WeaponsとMagicはパレット選択枠も含みます）。

* エディタは着色に必要なパレット番号（0〜3）を取得するため、Bank 0F の `CharBattlePaletteAssignment2`（初期値: `$3ECB4`）を参照します。
* 日本版ROMでは Bank 0F 後半のパレット関連コードが北米版より **143バイト後ろ（+0x8F）** に配置されています。
* 初期値の `$3ECB4` を参照すると、パレット番号ではなくプログラムコード（`0xF0` / 240等）が読み出されます。
* 読み出した値をパレット配列のインデックスとしてそのまま参照した結果、配列外アクセス（`IndexOutOfRangeException`）となり画面の初期化に失敗していました。

### 2.2 防具部位・移動中魔法の不整合要因（Bank 0E）

Bank 0E のデータ配置も、北米版と日本版でズレが存在します。

* **移動中魔法（Outside of Battle）**:
  日本版ROMでは、移動中魔法の判定ルーチンが北米版より **19バイト後ろ（+0x13）** に配置されています。初期設定番地（`MgCure: $3AF0A` 等）と合致しないため、エディタ側で「未割り当て（`--none--`）」として処理されていました。
* **防具部位（Armor Types）**:
  防具部位テーブル（体16、盾9、兜7、腕8）のアドレスも、初期値（`$3BCE1`）から **19バイト後ろ（`$3BCF4`）** に移動しています。

## 3. プロジェクト設定（.ff1d）の修正項目

日本版ROMの配置に適合させるため、`.ff1d` ファイル内の `RomValues`（アドレス設定）および `TextTables`（文字コードテーブル）を修正します。

### 3.1 画面起動エラー回避のための修正（Bank 0F）

Armor、Weapons、Magic エディタを起動可能にするための必須修正です。

| 設定項目名 (`Name`) | 北米版（初期値） | **日本版修正値 (+143 bytes / +0x8F)** | 内容 |
| :--- | :--- | :--- | :--- |
| **`CharBattlePaletteAssignment2`** | `$3ECB4` | **`$3ED43`** | クラス別戦闘パレット割り当てテーブル |
| **`BattlePaletteOffset`** | `$3EBB5` | **`$3EC44`** | 戦闘パレットテーブル本体 |

### 3.2 防具部位および移動中魔法の修正（Bank 0E）

防具種別を正しく判定させ、ケアル等の移動中効果を認識・編集可能にするための修正です。

| **`ArmorTypeOffset`** | `$3BCE1` | **`$3BCF4`** | 防具部位テーブル |
| **`MagicPermissionsOffset`** | `$3AD28` | **`$3AD3B`** | クラス別魔法習得制限テーブル |
| **`MgCure`** | `$3AF0A` | **`$3AF1D`** | 移動中魔法判定：ケアル |

| **`MgCur3`** | `$3AF18` | **`$3AF2B`** | 移動中魔法判定：ケアルダ |
| **`MgCur4`** | `$3AF1F` | **`$3AF32`** | 移動中魔法判定：ケアルガ |
| **`MgHeal`** | `$3AF26` | **`$3AF39`** | 移動中魔法判定：ヒール |
| **`MgHel2`** | `$3AF2D` | **`$3AF40`** | 移動中魔法判定：ヒーラ |

### 3.3 ウィンドウ色および特殊計算の修正（Bank 0F）

Bank 0F のシフト（+143バイト）に伴う、表示色およびモンク（BBMA）補正ルーチンの修正です。

| 設定項目名 (`Name`) | 北米版（初期値） | **日本版修正値 (+143 bytes / +0x8F)** | 内容 |
| :--- | :--- | :--- | :--- |
| **`MenuWindowColorOffset`** | `$3EB3A` | **`$3EBC9`** | メニュー枠色 |
| **`BattleWindowColorOffset`** | `$3EB3E` | **`$3EBCD`** | 戦闘枠色 |
| **`WindowGreyColorOffset`** | `$3EB48` | **`$3EBD7`** | 枠グレー色 |
| **`WindowWhiteColorOffset`** | `$3EB4D` | **`$3EBDC`** | 枠白色 |
| **`ShopBoxPaletteOffset`** | `$3EB84` | **`$3EC13`** | ショップ枠パレット |
| **`BbmaClass1UnadjOffset`** | `$3EED3` | **`$3EF62`** | モンク補正1 |
| **`BbmaClass2UnadjOffset`** | `$3EED7` | **`$3EF66`** | モンク補正2 |
| **`BbmaClass1ReadjOffset`** | `$3EEF1` | **`$3EF80`** | モンク再補正1 |
| **`BbmaClass2ReadjOffset`** | `$3EEF5` | **`$3EF84`** | モンク再補正2 |

### 3.4 文字コードテーブルの修正（TextTables）

日本版ROMの文字コード（0x00〜0xFF）に対応させるため、`TextTables` 内の `StdTable` および `DteTable` を256文字の日本語カナ・記号配列に更新します。

## 4. 設定の修正手順

手作業での修正も可能ですが、項目数が多いためパッチスクリプト（`patch_ff1d.py`）を使用して一括反映することを推奨します。

### 4.1 前提

* 対象のプロジェクトファイル（例: `FinalFantasy1.ff1d`）のパスを確認しておくこと。
* HAKKIN FF1 は終了した状態で実行すること。

### 4.2 実行コマンド

コマンドプロンプトより、対象の `.ff1d` ファイルパスを引数に指定してスクリプトを実行します。

```cmd
python patch_ff1d.py "W:\Dat\NES\ROM\_HACK_ROM\FF1\HakkinFF1_Project\FinalFantasy1\FinalFantasy1.ff1d"
```

### 4.3 処理結果の確認

1. 元のファイルと同じ場所に `.ff1d.bak`（バックアップ）が生成されていることを確認します。
2. 画面上に更新された項目一覧（`Kind: Offset` の確認ログ）が表示され、エラーなく終了することを確認します。
3. HAKKIN FF1 を起動してプロジェクトを開き、以下を確認します。
   * Armor、Weapons、Magic の各エディタが起動すること。
   * Magicエディタで「ケアル」を選択した際、Outside of Battle が `Cure`（Base: 16, Range: 15）と表示されること。
   * Armorエディタで防具の部位（Body, Shield, Head, Arms）が正しく表示されること。

### 4.4 留意事項

HAKKIN FF1 で新規プロジェクトを作成した直後は、ツール内部のテンプレート（北米版初期値）で `.ff1d` が再生成されます。日本版ROMで新しくプロジェクトを作成した際は、毎回このパッチ処理を実行する必要があります。
