## 概要

MSX1版の後期ROMは現時点で確認されていないため、MSX2版後期ロットの差分解析をもとに、MSX1版前期ROMへ同等の修正を適用するための技術記録とパッチプログラムです。

- MSX2版前期ロットと後期ロットの差分は 33,235 バイト（バンク 7, 9, 10, 11, 13, 14, 15, 38, 39, 40, 41）です。バンク0（起動エントリ・ROMヘッダ）は同一であり、メガロムのバンク切り替え方式にも違いはありません。
- 差分の大半は「コードや文字列の増減による配置ずれ」と「配置ずれに伴う参照アドレスの補正」です。実質的なロジック・データの変更は次の7種類です。

※ ソースコードは実装例です。

## 1. 実質的な変更

### 1.1 メッセージの変更（3件）

会話メッセージ（320件）、システムメッセージ（328件）における変更点は次の3件です。

| 箇所                                                | 前期                                          | 後期                                                         |
| :-------------------------------------------------- | :-------------------------------------------- | :----------------------------------------------------------- |
| 会話メッセージ269番（日本語、宇宙船の「予想誤差」） | `"予想誤差!３以内。"`（末尾 `'!'` が1バイト） | `"予想誤差+-３以内。"`（`"+-"` の2バイトに変更、+1バイト）   |
| システムメッセージ72番（英語）                      | `"Can't throw away for be too good"`          | `"Can't throw for be too good"`（`"away "` の5バイトを削除） |
| バンク7のスタッフロール                             | `"The Space Memoris"`                         | `"The Space Memories"`（`'e'` を1バイト挿入）                |

- 会話メッセージの英語文、システムメッセージの日本語文に違いはありません。
- 会話269番の +1 バイト増加に伴い、以降の文字列と英語会話メッセージテーブル（バンク39内）がすべて1バイト後ろへずれます。また、英語会話テーブルの先頭アドレスを参照している命令の即値（バンク15内、`59F8H` → `59F9H`）も1箇所補正されています。
- システム72番の -5 バイト削減に伴い、バンク40・41の後続文字列が5バイト前に詰まります。

### 1.2 銀製の剣と光の剣（バンク9、アドレス 48B8H のアイテム入手処理）

調べたマップチップの値によって渡すアイテムを決定する処理です。値が `71H` の場合が剣入手の分岐になります。

- 前期: 条件を満たすと、無条件で光の剣（アイテム番号6）を渡します。
- 後期: 渡す前にフラグ `D093H` を判定する処理が追加されています。フラグが立っていれば光の剣、立っていなければ銀製の剣（アイテム番号4）を渡します。

フラグ `D093H` およびそれを立てる処理自体は前期にも存在します（T&Eパック（アイテム番号54）を使用すると消費されて `D093H=1` になり、メッセージ `0101H` が出力されます）。後期で追加されたのはアイテムを渡す側のフラグ判定のみであり、正規手順自体は前期から用意されていたものです。

変更位置: バンク9 オフセット `08E8H`（アドレス `48E8H`）。前期の8バイトが後期では22バイトになります（+14バイト）。

```text
前期 (8バイト):
  21 DA D0 3E 06 C3 17 48
  (LD HL,D0DAH / LD A,6 / JP 4817H)

後期 (22バイト):
  3A 93 D0 B7 28 08 21 DA D0 3E 06 C3 17 48
  21 DA D0 3E 04 C3 17 48
  (LD A,(D093H) / OR A / JR Z,+8 / 光の剣 / 銀製の剣)
```

### 1.3 湖の宮殿のコンピュータ暴走バグ修正（バンク9、アドレス 49D7H）

前期ロットで「湖の宮殿でコンピュータの左端を調べると暴走する」バグの修正箇所です。メッセージ315番 `"Memory bank of Computer"` および266番を表示し、宇宙コンパス（アイテム番号65）を渡す処理です（隣接処理は宇宙服（アイテム番号66）を渡します）。

書き換えられたのは最初の判定ブロックです。

```text
前期 (14バイト):
  01 01 0D CD F5 BE 2A A5 D0 2C B7 ED 42 C8
  LD BC,0D01H / CALL BEF5H (座標検索) / LD HL,(D0A5H)
  INC L / OR A / SBC HL,BC / RET Z

後期 (13バイト):
  ED 4B A5 D0 0C CD 6B BD CB 76 CA 48 41
  LD BC,(D0A5H) / INC C / CALL BD6BH (マップチップ取得)
  BIT 6,(HL) / JP Z,4148H
```

後期の判定は、隣接する宇宙服の処理が使う判定と同一です。前期の「座標を検索して現在位置と比較する」判定が特定座標（左端）で想定外の挙動を起こしていたものを、隣接処理と同じ「マップチップの Bit 6 を確認する」判定へ置き換えています。2段目の判定（マップチップ値が13かどうかの確認）は前期・後期で同一です。

変更位置: バンク9 オフセット `09D7H`。14バイトが13バイトになります（-1バイト）。剣入手処理の +14 バイトと合わせて、バンク9+10の連続領域は差し引き +13 バイトずれるため、バンク10 オフセット `03A0H` 付近から並ぶ `00H` の空き領域13バイト分を詰めてサイズを合わせています。

### 1.4 キー入力ルーチンの置換（バンク15、エントリアドレス AC7EH）

`A000H` 台の共通バンクに配置されているキー入力ルーチンが全面的に書き換えられています。

- 前期（87バイト）: キーコード `BFH` 用、`30H` 台用、その他で判定を分岐し、16bitカウンタ `DC8FH` およびカウンタ `DC91H`/`DC92H` を使用します。
- 後期（49バイト）: 判定を一本化し、カウンタは `DC8FH` を1バイトカウンタとして使用して `DC91H`/`DC92H` は使用しません。

後期では38バイト（`26H` バイト）短くなったため、バンク15のキー入力ルーチンより後ろの領域がすべて `26H` バイト前に詰まります。これに伴い、キー入力ルーチンより後ろ（`ACD5H` 以降）を指す参照アドレスは、他のバンクを含めてすべて `26H` 減算されています（付録C、合計740件）。なお、読み取りサブルーチン自体のアドレスは前期 `ACD5H` → 後期 `ACAFH` に移動していますが、サブルーチンのコード内容は同一です。

### 1.5 バンク13の初期化処理（アドレス 5B5CH）

ワーク `D08CH` のフラグにより、2回目以降はスキップされる初期化系の処理です。

```text
前期の末尾 (11バイト、5B6CH〜):
  3E 01 32 8C D0 CD E5 A5 C3 AF 4E
  LD A,1 / LD (D08CH),A / CALL A5E5H / JP 4EAFH

後期の末尾 (17バイト):
  31 00 F0 3E 01 32 8C D0 CD E5 A5 CD AF 4E C3 22 40
  LD SP,0F000H / LD A,1 / LD (D08CH),A / CALL A5E5H
  CALL 4EAFH / JP 4022H
```

先頭にスタックポインタの再設定（`LD SP,0F000H`）が追加されました。スタックリセットによって呼び出し元への戻りアドレスが失われるため、末尾の `JP 4EAFH` を `CALL 4EAFH` に変更して処理を実行させた後、確実に `4022H` へ遷移する構成になっています。+6バイト増加するため、バンク13のこの位置より後ろの配置がすべて6バイト後ろへずれます。

### 1.6 ウェイトループのカウンタ値変更（6箇所）

キー入力ルーチンを呼び出すウェイト処理などで、待機回数・ループ回数の指定が変更されています。

| バンク | オフセット | 変更内容                                                       |
| :----- | :--------- | :------------------------------------------------------------- |
| 9      | 00A0H      | `LD HL` の即値 `0800H` → `0200H`（上位バイト `08H` → `02H`） |
| 10     | 084DH      | `LD HL` の即値 `0800H` → `0200H`（同上）                      |
| 11     | 0510H      | `LD HL` の即値 `3000H` → `0C00H`（上位バイト `30H` → `0CH`） |
| 13     | 0431H      | `LD HL` の即値 `3000H` → `0C00H`（同上）                      |
| 13     | 13E2H      | `LD HL` の即値 `0200H` → `0400H`（上位バイト `02H` → `04H`） |
| 13     | 03C3H      | 繰り返し回数 `LD B,4` → `LD B,8`                              |

### 1.7 バンク14の差分の構造（バンク14自体のロジック変更はなし）

バンク14自体に後期独自のコード・データ変更はなく、差分はすべてバンク13の +6 バイト挿入に連動した配置ずれとアドレス補正によるものです。

バンク13とバンク14は、合わせて「マップごとのイベントテーブル」を構成しています。

- バンク13末尾にディスパッチテーブル（33エントリ×4バイト、アドレス `5F81H`〜）があり、各エントリは「イベントレコードの先頭アドレス」と「ジャンプテーブルの先頭アドレス」を保持します。
- 各イベントレコードはバンク14側に配置され、`[件数][キー配列][ジャンプテーブル]` の構造を持ちます。ジャンプテーブル内のハンドラ（ジャンプ先）はバンク13側の処理です。
- ディスパッチ処理（バンク13、`503FH`）はワーク `D09FH`（マップ番号 `0〜32`）でディスパッチテーブルを引き、キー配列から `D09EH` と一致するものを検索して、対応するハンドラを呼び出します。
- バンク13とバンク14は実行空間 `4000H〜7FFFH` に連続して配置されており、ディスパッチテーブルの末尾はバンク13からバンク14先頭へ5バイトはみ出しています。

後期では 1.5 節の +6 バイト挿入によってディスパッチテーブル全体が6バイト後ろへずれ、バンク14側へのはみ出しが5バイトから11バイトに増えました。これに伴ってバンク14の中身全体が6バイト後ろへずれています。バンク14先頭に増えた3件分のデータ（`61C5H`/`61D7H`/`61DFH`）は、はみ出し増加分によってバンク14側に入り込んだディスパッチテーブル末尾（レコード29・30のエントリ）そのものです。イベントレコードの内容（キー配列とハンドラの対応）は前期と完全に同一であり、残りの差分も各ハンドラやコード内の参照アドレス補正（`6` 加算および `26H` 減算）ですべて説明できます。


## 2. 配置のずれに伴うアドレス補正

コードや文字列の長さ変更によって後続の配置がずれるため、ずれた範囲を指す参照アドレスをすべて補正する必要があります。各領域のずれ方は次の通りです。

| 領域                              | ずれ方                                                                                                          |
| :-------------------------------- | :-------------------------------------------------------------------------------------------------------------- |
| バンク7                           | オフセット `114EH` 以降が +1 バイト                                                                             |
| バンク9+10（連続領域として）      | オフセット `08F0H〜09D6H` が +14 バイト、`09EBH〜23A0H` が +13 バイト、以降は元通り（バンク10の空き領域で吸収） |
| バンク13                          | オフセット `1B6CH` 以降が +6 バイト                                                                             |
| バンク14                          | 全体が +6 バイト（1.7節のはみ出し増加分）                                                                       |
| バンク15                          | `AC7EH` のキー入力ルーチンを置換し、オフセット `0CD5H` 以降が 26H バイト前に詰まる（`-26H`）                    |
| バンク38+39（会話メッセージ）     | メッセージ269番の文字列以降が +1 バイト                                                                         |
| バンク40+41（システムメッセージ） | メッセージ72番の文字列以降が -5 バイト                                                                          |
| バンク11                          | 配置ずれなし（バンク15への参照アドレス補正のみ）                                                                |

アドレス補正は「実際にアドレスとして参照されている箇所のみを対象にする」必要があります。ずれたアドレス範囲と一致する2バイト値を無差別に書き換えると、命令列や非アドレスデータ内の偶然一致したバイト列（例：`CALL` 命令のオペコードとジャンプ先下位バイトの組み合わせ等）まで破壊するためです。付録A〜Eは、命令オペランドやテーブルエントリとして参照されている確定対象の一覧です。なお、バンク13内の自バンク参照（付録B先頭の34件）については、「直前バイトが16bit即値/絶対アドレスをオペランドに取るZ80命令のオペコードである箇所」というルールでも過不足なく抽出できます。


## 3. ソースコード例

前期・後期の双方を単一ソースからビルドする場合は、以下の構成が考えられます。

- 変更のないバンクは、元ROMから切り出したバイナリをそのまま取り込む（`INCBIN`）。
- 変更のある箇所はラベルを付け、`IF` ディレクティブで前期形・後期形を切り替える。アドレスを数値直書きではなくラベル参照にすることで、挿入に伴うジャンプ先やテーブルの再計算をアセンブラに任せられます（たとえば 1.1 節の英語会話テーブル `59F8H`/`59F9H` もラベル化すれば手動補正が不要になります）。

※ `sjasmplus` や `AILZ80ASM` のようにメガロムバンク対応の `ORG` ディレクティブを持つ環境でアセンブルできます。

バンク切り出しスクリプトの例:

```python
# cut_banks.py — 元ROMを8KBバンクごとに切り出す
import sys
rom = open(sys.argv[1], "rb").read()
for bank in range(64):
    with open(f"bank{bank:02d}.bin", "wb") as f:
        f.write(rom[bank * 0x2000:(bank + 1) * 0x2000])
```

剣入手処理（1.2節）の例:

```asm
; バンク9、48E8H — マップチップ値 71H の場合の分岐続き
    IF LATE
        ld      a,(0D093h)      ; T&Eパック使用フラグ
        or      a
        jr      z,.silver
        ld      hl,0D0DAh
        ld      a,6             ; 光の剣
        jp      give_item       ; 4817H
.silver:
        ld      hl,0D0DAh
        ld      a,4             ; 銀製の剣
        jp      give_item
    ELSE
        ld      hl,0D0DAh
        ld      a,6             ; 前期は無条件で光の剣
        jp      give_item
    ENDIF
```

メモリバンク判定（1.3節）の例:

```asm
; バンク9、49D7H — 最初の判定
    IF LATE
        ld      bc,(0D0A5h)
        inc     c
        call    grid_lookup     ; BD91H (後期では26Hバイト前に詰まり BD6BH)
        bit     6,(hl)
        jp      z,event_exit    ; 4148H
    ELSE
        ld      bc,00D01h
        call    grid_search     ; BEF5H
        ld      hl,(0D0A5h)
        inc     l
        or      a
        sbc     hl,bc
        ret     z
    ENDIF
```

バンク13初期化処理末尾（1.5節）の例:

```asm
    IF LATE
        ld      sp,0F000h
    ENDIF
        ld      a,1
        ld      (0D08Ch),a
        call    L_A5E5
    IF LATE
        call    L_4EAF
        jp      L_4022
    ELSE
        jp      L_4EAF
    ENDIF
```

ディスパッチテーブルとイベントレコード（1.7節）の例:

```asm
; バンク13の末尾 — このままバンク14の先頭へ続く
dispatch_table:
        dw      rec_00, rec_00_ptrs
        dw      rec_01, rec_01_ptrs
        ; …33エントリ…
        dw      rec_32, rec_32_ptrs

; バンク14のイベントレコードの例 (レコード29)
rec_29:
        db      9                       ; 件数
        db      0,1,2,3,4,5,6,7,8       ; キー配列 (D09EHと比較する値)
rec_29_ptrs:
        dw      L_5E94, L_5E94, L_5E94, L_5E94
        dw      L_5E9E, L_5EB2, L_5EC4, L_5E94, L_5E94
```

キー入力ルーチン（1.4節、後期版）の例:

```asm
kb_entry:               ; AC7EH、読み取りサブルーチンは kb_reader (後期 ACAFH)
        push    hl
        call    kb_reader
        ld      h,a
        ld      a,(0DC8Eh)
        cp      h
        jr      nz,kb_new
        ld      a,h
        and     0F0h
        cp      0B0h
        jr      nz,kb_bf
        ld      a,h
        ld      hl,0DC8Fh
        dec     (hl)
        jr      z,kb_reset
kb_bf:
        pop     hl
        ld      a,0BFh
        ret
kb_reset:
        ld      h,a
        ld      a,32h
        ld      (0DC8Fh),a
        ld      a,h
        pop     hl
        ret
kb_new:
        ld      a,0FAh
        ld      (0DC8Fh),a
        ld      a,h
        ld      (0DC8Eh),a
        pop     hl
        ret
```

全体の組み立ては、バンクごとに `ORG` を指定して配置し、`LATE` の定義（0 または 1）を切り替えてアセンブルします。変更のないバンクは `incbin "bank00.bin"` のように取り込みます。


## 4. MSX1版への適用

`make_msx1_late.py` は、MSX1版前期ROMを後期相当に変換するパッチプログラムです。

- 検証機能（`--profile msx2`）: 同一の変換ロジックをMSX2版前期ROMに適用した場合、MSX2版特有のディスパッチテーブル境界跨ぎによるバンク14全体ずれを除き、他の全バンクがMSX2版後期ROMとバイト単位で一致します。
- MSX1版で変更されるバンクは 5, 9, 10, 11, 13, 14, 15, 38, 39, 40, 41 です。スタッフロールはMSX1版ではバンク5にあります。
- MSX1版のキー入力ルーチンは `A930H` に配置されています。後続サブルーチン（`A985H`）のアドレスを動かさないよう余剰領域を `00H` でパディングして後期版ロジックを書き込むため、バンク15の `26H` バイト詰めは発生せず、付録C相当のアドレス補正は不要です。
- MSX1版でメモリバンク判定処理が呼び出すサブルーチンは `B978H` と `B989H` です（MSX2前期の `BD91H` と `BDA2H` に相当）。MSX1版ではバンク15の配置がずれないため、このアドレスのまま使用します（MSX1版の `BD91H` 付近は `00H` で埋められた空き領域です）。
- MSX1版のディスパッチテーブルはバンク13内に収まっているため（`5F6CH`〜）、バンク14全体は動かしません。代わりに以下の2点を行います。
  - バンク14内のイベントジャンプテーブルのうち、バンク13への +6 バイト挿入でずれる範囲を指すハンドラアドレス72件（付録E）に `6` を加算。
  - エントリ0が指すレコード0（31バイト）はバンク13末尾（`5FF0H`）からバンク14先頭にまたがって配置されており、+6 バイト挿入によって途中のバイトが押し出されて欠損するため、レコード0をバンク14末尾の空き領域（`7FE1H`）へ退避し、ディスパッチテーブルの先頭エントリを退避先アドレスへ更新。
